## Q0. Is OpenCode fully agentic and does it execute tools?

### Takeaway
Yes, verified at code level: OpenCode runs an unbounded tool-calling loop (`runLoop` in `session/prompt.ts`, `while (true)`, `maxSteps = agent.steps ?? Infinity`) over Vercel AI SDK `streamText`, executes tool calls concurrently as they stream in (`session/processor.ts`), feeds results/errors back as tool-result parts, auto-compacts on context overflow, retries provider errors with backoff, and stops only when the model finishes without tool calls (or hits max steps / a permission rejection).

### Cited Findings
- Main loop: `runLoop` processes messages in `while (true) { yield* status.set(sessionID, { type: "busy" }) ... }`; steps increment (`step++`), `const maxSteps = agent.steps ?? Infinity; const isLastStep = step >= maxSteps`; on the last step `MAX_STEPS_PROMPT` is injected — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- Loop exit condition: `if (lastAssistant?.finish && !["tool-calls", "unknown"].includes(lastAssistant.finish) && !hasToolCalls && lastAssistant.parentID === lastUser.id) { break }`; tool calls detected as `part.type === "tool" && !part.metadata?.providerExecuted` — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- LLM call is `streamText({...})` from the Vercel AI SDK with `tools: prepared.tools`, `toolChoice`, `activeTools: Object.keys(prepared.tools).filter((x) => x !== "invalid")`, `maxRetries: input.retries ?? 0`, `abortSignal: input.abort` — [SRC/session/llm.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm.ts)
- Tool calls "execute concurrently as they arrive via the stream", each tracked in `ctx.toolcalls[input.id] = { done: yield* Deferred.make<void>(), partID, messageID, sessionID }`; cleanup waits with `Effect.forEach(..., { concurrency: "unbounded" })` (summary) — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- `process()` returns `"compact"` when `ctx.needsCompaction`, `"stop"` when `ctx.blocked || ctx.assistantMessage.error`, else `"continue"` — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- Headless: `opencode run` — "Run opencode in non-interactive mode by passing a prompt directly"; JSON event stream with `--format json` — [DOCS/cli](https://opencode.ai/docs/cli/)

### Inferences
- The loop is structurally the same shape as Claude Code's (user msg → stream → execute tool calls → append results → re-call until no tool calls), so porting the mechanisms below into a Python harness is a matter of reproducing the state machine, not inventing a new one.

### Gaps
- None for this question.

## Q2. Agent loop: session/turn/step, streaming, parallel tools, max steps, doom loop, retries, finish reasons, empty responses, storage, resume/share/fork/compaction

### Takeaway
A session is a SQLite-backed list of messages (`message` table) and parts (`part` table, JSON `data` columns); each user prompt starts `runLoop`, which per step assembles the system prompt (provider prompt + `<env>` + instruction files + MCP instructions + skills), calls `streamText`, executes tool calls concurrently as they stream, checks token overflow after every `step-finish` and auto-compacts, detects doom loops after 3 identical consecutive calls (permission `doom_loop`), and retries provider errors up to 5 times with 2s×2^n jittered backoff; `finish_reason: length` has no special branch (overflow is token-count based), and empty responses have no explicit retry.

### Cited Findings
Step / loop mechanics
- Per step the system prompt is assembled from `sys.skills(agent)`, `sys.environment(model)`, `instruction.system()`, `sys.mcp(agent, session.permission)`: `const system = [...env, ...instructions, ...(mcpInstructions ? [mcpInstructions] : []), ...(skills ? [skills] : [])]`; for structured output `STRUCTURED_OUTPUT_SYSTEM_PROMPT` is appended and a `StructuredOutput` tool is created (`tools["StructuredOutput"] = createStructuredOutputTool({...})`) — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- Overflow check at the top of each iteration: `if (lastFinished && lastFinished.summary !== true && (yield* compaction.isOverflow({ tokens: lastFinished.tokens, model }))) { yield* compaction.create({ sessionID, agent: lastUser.agent, model: lastUser.model, auto: true }); continue }`; when the processor returns `"compact"`, compaction is created with `overflow: !handle.message.finish` — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- Subtask user parts route to `handleSubtask(...)`; `TaskTool` executes subtask prompts with `bypassAgentCheck: true` — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- Finish-reason handling: `"stop"`, `"tool-calls"`, `"unknown"` continue the loop logic; `"content-filter"` ends with error; other finish values with no tool calls break; `"length"` is not mentioned anywhere in prompt.ts (summary) — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- No explicit empty-response retry or synthetic message exists in prompt.ts (summary); user message part inputs accepted: `Schema.Union([SessionV1.TextPartInput, SessionV1.FilePartInput, SessionV1.AgentPartInput, SessionV1.SubtaskPartInput])` — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- Interrupt finalization: `msg.error ??= MessageV2.fromError(new DOMException("Aborted", "AbortError"), { providerID: msg.providerID, aborted: true }); msg.time.completed = Date.now()` — [SRC/session/prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)
- `MAX_STEPS_PROMPT` (verbatim): "CRITICAL - MAXIMUM STEPS REACHED\n\nThe maximum number of steps allowed for this task has been reached. Tools are disabled until next user input. Respond with text only.\n\nSTRICT REQUIREMENTS:\n1. Do NOT make any tool calls (no reads, writes, edits, searches, or any other tools)\n2. MUST provide a text response summarizing work done so far\n3. This constraint overrides ALL other instructions, including any user requests for edits or tool use\n\nResponse must include:\n- Statement that maximum steps for this agent have been reached\n- Summary of what has been accomplished so far\n- List of any remaining tasks that were not completed\n- Recommendations for what should be done next\n\nAny attempt to use tools is a critical violation. Respond with text ONLY." — [CORE/session/runner/max-steps.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/runner/max-steps.ts)
- Agent `steps` = "Max agentic iterations before text-only response"; `maxSteps` deprecated — [DOCS/agents](https://opencode.ai/docs/agents/)

Stream processing (`session/processor.ts`)
- Events handled: `text-start/delta/end` (text-end triggers `plugin.trigger("experimental.text.complete", ...)`), `reasoning-start/delta/end`, `tool-input-start/delta/end` (→ `ensureToolCall`), `tool-call` (doom-loop check, then state `{ status: "running", input, time: { start } }`), `tool-result` (→ `completeToolCall`, state `completed`), `tool-error` (→ `failToolCall`, state `{ status: "error", error: errorMessage(error) }`), `step-start` (snapshot), `step-finish` (usage tokens/cost, overflow check) — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- Doom loop: `const DOOM_LOOP_THRESHOLD = 3`; `const recentParts = parts.slice(-DOOM_LOOP_THRESHOLD)`; returns unless every recent part is `part.type === "tool" && part.tool === value.name && part.state.status !== "pending" && JSON.stringify(part.state.input) === JSON.stringify(input)`; then `permission.ask({ permission: "doom_loop", patterns: [value.name], ... })` — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- If a tool error is `PermissionV1.RejectedError` or `Question.RejectedError`, `ctx.blocked = ctx.shouldBreak` (loop stops) — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- Overflow after step-finish: `isOverflow({ cfg, tokens: usage.tokens, model })` → `ctx.needsCompaction = true`, stream halted via `Stream.takeUntil(() => ctx.needsCompaction)`; on overflow *errors* in `halt`, if auto-compaction disabled and no summary exists it returns early, else sets `needsCompaction` — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- Retry wrapper: `Effect.retry(SessionRetry.policy({ provider, parse, set }))`, publishing status `{ type: "retry", attempt, message, action, next }` — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)
- Image outputs that cannot be resized are dropped with `"[N image(s) omitted: could not be resized below the image size limit.]"` — [SRC/session/processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)

Retry policy (`session/retry.ts`)
- Always retried: HTTP 5xx and 429; message regexes for "rate limit", "too many requests", "rate increased too quickly", "overloaded", "service unavailable", "internal error", "connection refused", "socket hang up", "fetch failed", "request timeout", "timed out", "resource exhausted", "try again later", "temporarily at capacity"; `ContextOverflowError` explicitly excluded; backoff `delay = (2000 × 2^(attempt-1)) + jitter` (factor 2.0, jitter 0.25), cap 30 s without headers; honours `retry-after-ms` then `retry-after` (seconds or HTTP date); max 5 retries (summary) — [SRC/session/retry.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/retry.ts)
- AI SDK-level retries are disabled (`maxRetries: input.retries ?? 0`) so OpenCode's own policy governs — [SRC/session/llm.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm.ts)

Compaction / overflow / prune
- Overflow formula: overflow when `count >= usable`, `count = tokens.total || (input + output + cache.read + cache.write)`, `usable = (model.limit.input || (context - maxOutputTokens)) - reserved`, `reserved = compaction.reserved ?? min(20_000, maxOutputTokens)`; returns false if `compaction.auto === false` or `model.limit.context === 0` (summary) — [SRC/session/overflow.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/overflow.ts)
- `OUTPUT_TOKEN_MAX = 32_000`; `maxOutputTokens(model) = Math.min(model.limit.output, outputTokenMax) || outputTokenMax` — [SRC/provider/transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)
- Prune: `PRUNE_PROTECTED_TOOLS = ["skill"]`, `PRUNE_MINIMUM = 20_000` (tokens that must be freed), `PRUNE_PROTECT = 40_000` (most recent tool-output tokens kept); walks messages backwards, marks older completed tool outputs `part.state.time.compacted = Date.now()` — [SRC/session/compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)
- Compaction produces an assistant message `{ role: "assistant", mode: "compaction", agent: "compaction", summary: true, ... }`; plugin hook `plugin.trigger("experimental.session.compacting", { sessionID }, { context: [], prompt: undefined })` can inject context or replace the prompt; prompt built by `buildPrompt({ previousSummary, context: [conversation] })` — [SRC/session/compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)
- Summary prompt: "Create a new anchored summary from the conversation history in the <conversation> tags above so another coding agent can continue the work."; required Markdown sections Objective / Important Details / Work State (Completed, Active, Blocked) / Next Move / Relevant Files; "Keep every section, even when empty. Use terse bullets, not prose paragraphs. Preserve exact file paths, symbols, commands, error strings, URLs, and identifiers when known."; with a prior summary: "Carry forward objectives, constraints, user directives, decisions, and parallel workstreams from the <prior-summary> even when the <conversation> does not mention them." — [CORE/session/compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/compaction.ts)
- Config: `"compaction": { "auto": true, "prune": false, "reserved": 10000 }`; env `OPENCODE_DISABLE_AUTOCOMPACT`, `OPENCODE_DISABLE_PRUNE` — [DOCS/config](https://opencode.ai/docs/config/), [DOCS/cli](https://opencode.ai/docs/cli/)
- Pruned outputs are replayed to the model as `"[Old tool result content cleared]"` with attachments removed; tool parts still `pending`/`running` at replay time become `state: "output-error"`, `errorText: "[Tool execution was interrupted]"`; error parts become `output-error` with `errorText: part.state.error` (or `output-available` if an interrupted call left string output); assistant messages with no remaining parts are skipped; media not supported inside tool results is injected as a synthetic user message prefixed "Attached media from tool result:" — [SRC/session/message-v2.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/message-v2.ts)
- Reasoning parts are replayed with original `text` and `providerMetadata`; if the model changed since, empty reasoning is dropped and non-empty reasoning becomes plain text — [SRC/session/message-v2.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/message-v2.ts)

### Inferences
- OpenCode has no Bash-level "sandbox"; safety is entirely permission rules + the tree-sitter command parse, which is why `bash` patterns can be matched per sub-command (`git *` etc.). A no-safety-heuristics harness can drop the parse and keep the rest.
- The `invalid` pseudo-tool + case-insensitive name repair is the main reason weak tool callers (DeepSeek/Qwen/GLM) recover instead of crashing the turn; combined with `activeTools` excluding `invalid`, the model never sees it as callable.
- The edit replacer chain is the single most portable piece: pure string algorithms with explicit thresholds (0.65 Levenshtein, 50% context lines, span-size guards).

## Q4. Permissions: config, agent overrides, skip-permissions equivalents, TUI/headless surfacing, auto mode

### Takeaway
Permissions are rulesets of `{ permission, pattern, action }` (`allow|ask|deny`) built from the `permission` config (string shorthand or per-pattern objects), agent overrides, session-scoped "always" approvals and built-in defaults; evaluation is `findLast` over the flattened rulesets (last matching rule wins, default `ask`), patterns use `*`/`?` wildcards anchored and case-insensitive on Windows; `--auto`/`OPENCODE_PERMISSION` are the skip-permissions equivalents, and headless `opencode run` auto-rejects any ask unless `--auto`.

### Cited Findings
- Values: `"allow"` executes without approval, `"ask"` prompts, `"deny"` blocks; keys: `read`, `edit`, `glob`, `grep`, `bash`, `task`, `skill`, `lsp`, `question`, `webfetch`, `websearch`, `external_directory`, `doom_loop`; syntax `{ "permission": { "*": "ask", "bash": "allow", "edit": "deny" } }` and `{ "permission": { "bash": { "*": "ask", "git *": "allow", "rm *": "deny" } } }`; "Pattern matching uses wildcards: `*` (zero or more characters) and `?` (exactly one character)"; TUI replies `once`, `always` ("approve matching patterns for current session"), `reject`; agent rules merge over global with agent precedence; "Most permissions default to `"allow"`. Notable exceptions: `doom_loop` and `external_directory` default to `"ask"`. The `read` permission denies `.env` files by default." — [DOCS/permissions](https://opencode.ai/docs/permissions/)
- `--auto`: "Launch with `--auto` flag to automatically approve requests not explicitly denied: `opencode --auto` / `opencode run --auto "Refactor this module"`" — [DOCS/permissions](https://opencode.ai/docs/permissions/); `OPENCODE_PERMISSION` = "Inlined json permissions config" — [DOCS/cli](https://opencode.ai/docs/cli/)
- `evaluate()` verbatim: `export function evaluate(permission: string, pattern: string, ...rulesets: PermissionV1.Ruleset[]): PermissionV1.Rule { return ( rulesets.flat().findLast((rule) => Wildcard.match(permission, rule.permission) && Wildcard.match(pattern, rule.pattern)) ?? { action: "ask", permission, pattern: "*" } ) }` — [SRC/permission/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/permission/index.ts) (re-exported by [SRC/permission/evaluate.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/permission/evaluate.ts))
- `ask()` loops patterns: `if (rule.action === "deny") { return yield* new PermissionV1.DeniedError(...) } if (rule.action === "allow") continue; needsAsk = true` — deny wins immediately, all-allow skips the prompt, otherwise a prompt is raised — [SRC/permission/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/permission/index.ts)
- Request shape `{ id?, sessionID, permission, patterns: string[], metadata?, always?: string[], tool? }`; pending map `Map<ID, { info, deferred }>`; reply `"reject"` fails with `RejectedError` (or `CorrectedError({ feedback })` when a message is supplied), `"once"` succeeds without persisting, `"always"` pushes `{ permission, pattern, action: "allow" }` for each `info.always` pattern into the session's in-memory `approved` array (not written to config); `fromConfig()` turns string shorthand into `{ permission: key, action: value, pattern: "*" }` and nested objects into per-pattern rules with `~/`/`$HOME` expansion; events `Event.Asked`, `Event.Replied` — [SRC/permission/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/permission/index.ts)
- V2 error classes in core: `PermissionV2.BlockedError { rules }`, `PermissionV2.DeclinedError {}`, `PermissionV2.CorrectedError { feedback }` — [CORE/permission.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/permission.ts)
- `Wildcard.match`: escapes regex specials, `*` → `.*`, `?` → `.`, anchored `^...$`, flags `si` on Windows and `s` elsewhere, backslashes normalised to `/`, and a trailing " *" becomes optional (`" .*"` → `"( .)?"`) so `git *` also matches bare `git` (summary) — [SRC/util/wildcard.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/util/wildcard.ts)
- Built-in agent defaults (agent.ts): base rules `doom_loop: "ask"`, `external_directory: { "*": "ask" }`, `question: "deny"`, `plan_enter`/`plan_exit: "deny"`, `"*.env"` read `"ask"`; build adds `question: "allow"`, `plan_enter: "allow"`; plan adds `question: "allow"`, `plan_exit: "allow"`, `edit: { "*": "deny" }` except `.opencode/plans/*.md`; general adds `todowrite: "deny"`; explore allows only `grep`, `glob`, `read`; compaction/title/summary are hidden with `"*": "deny"` (summary) — [SRC/agent/agent.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/agent/agent.ts)
- Headless: `opencode run` handles `permission.asked` with `if (auto) { await client.permission.reply({ requestID: permission.id, reply: "once" }) } else { await client.permission.reply({ requestID: permission.id, reply: "reject" }) }`; non-interactive sessions get `[{ permission: "question", action: "deny", pattern: "*" }, { permission: "plan_enter", action: "deny", pattern: "*" }, { permission: "plan_exit", action: "deny", pattern: "*" }]` — [SRC/cli/cmd/run.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/cli/cmd/run.ts)
- Server surfacing: `POST /session/:id/permissions/:permissionID` answers a request; `GET /global/event` streams `permission.asked`/`permission.replied` — [DOCS/server](https://opencode.ai/docs/server/), [DOCS/plugins](https://opencode.ai/docs/plugins/)
- Plugin hook `permission.ask: (input: Permission, output: { status: "ask" | "deny" | "allow" })` lets a plugin auto-decide — [packages/plugin/src/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/plugin/src/index.ts)
- Tools ask with `always: ["*"]` (read/edit/grep/webfetch) so a single "always" approval whitelists the whole tool for the session; skill asks with `always: [params.name]` — [SRC/tool/read.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/read.ts), [SRC/tool/edit.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/edit.ts), [SRC/tool/skill.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/skill.ts)
- Legacy `tools: { "write": false, "bash": false }` config still exists to disable tools outright; MCP tools can be disabled with globs `"tools": { "my-mcp*": false }` — [DOCS/config](https://opencode.ai/docs/config/), [DOCS/mcp-servers](https://opencode.ai/docs/mcp-servers/)

### Inferences
- Because default-when-unmatched is `ask` in `evaluate()`, the "most permissions default to allow" behaviour in the docs must come from a `"*": "allow"`-style base rule in the built-in agent defaults; a harness that wants Claude-Code-like "ask" defaults should just omit that base rule.
- A "no safety heuristics" harness can reproduce `--auto` semantics exactly: evaluate rules, treat `ask` as `allow`, keep `deny`.
- `.env` handling differs between docs ("denies") and agent.ts ("ask"); treat the code as current.

### Gaps
- Exact text of the V1 `DeniedError`/`RejectedError` messages that the model sees was not located (they are defined outside `permission/index.ts`).
- `arity.ts` (structured/whitespace-aware pattern matching for bash) was not read; `Wildcard.allStructured/matchSequence` exist but their use in bash matching is inferred.

- The `{env:}`/`{file:}` substitution plus `OPENCODE_CONFIG_CONTENT`/`OPENCODE_PERMISSION` inline JSON are what make OpenCode scriptable in CI; a Python harness reusing Claude Code's `settings.json` would need an adapter that emits the same rule model (`permission` object → rulesets).
- Nested command directories are flattened by prefix stripping; the exact separator for nested names was not visible, so treat command names as path-derived strings.

### Gaps
- Exact `Flag.OPENCODE_DISABLE_CLAUDE_CODE*` definitions were not found in `packages/core/src/flag/flag.ts` (referenced as `flags.disableClaudeCodePrompt` / `disableClaudeCodeSkills` elsewhere); documented behaviour is taken from the CLI/rules docs.
- Config-directory scanning for skills/plugins in `config.ts` is delegated to `ConfigAgent/ConfigCommand/ConfigPlugin` modules; only agent and command loaders were read.

## Q6. Claude Code compatibility: what OpenCode reads from `~/.claude`, MCP from `~/.claude.json`, `claude` provider/OAuth, migration docs

### Takeaway

## Q7. Known issues relevant to open-weight models, headless runs, session corruption and Linux terminals

### Takeaway
The recurring failure classes are: (1) reasoning-replay 400s with DeepSeek/Kimi thinking modes and OpenRouter (dropped or rewritten `reasoning_content`), (2) malformed/empty tool-call JSON from GLM-5, Kimi K2/K2.5 and Qwen 3.x via OpenAI-compatible endpoints (including "" tool names and strict-schema rejections of `{}` params), (3) headless hangs when the model calls `question` or a subagent asks for permission, (4) JSON/SQLite storage corruption after disk-full/crash and migration gaps, and (5) OpenTUI/tmux/kitty input-encoding problems on Linux.

- OpenCode's `transform.ts` already contains the fixes for several of these (DeepSeek empty-reasoning insertion, Moonshot `$ref` stripping, OpenAI-compatible reasoning relocation), so a harness should: always replay `reasoning_content` verbatim on tool-call turns for DeepSeek/Kimi, emit `"required": []` for empty-param tools, and route empty/unknown tool names through an `invalid`-style tool rather than aborting.
- Headless-run hangs are architectural (an unanswered `permission.asked`/`question` blocks a Deferred forever); a harness must auto-answer or pre-deny these in non-interactive mode exactly as run.ts does.
