# Databricks as the model source for an agentic coding harness (state as of 2026-09-23)

Scope: how open models (DeepSeek, Kimi, Qwen, GLM, Llama, Gemma) and Claude/GPT/Gemini are served and called on Databricks, and the exact wire formats a Claude-Code-like harness ("halo") or third-party harness (DeepSeek's harness, OpenRouter "ori", OpenCode/Codex/Cline-style tools) must speak.

Big-picture correction to the assignment's assumptions (verified 2026-09-22/23 docs):

- "Mosaic AI Gateway" has been renamed **Unity Gateway** (a.k.a. "Unity AI Gateway"). Governed LLM access is now modelled as **model services** — Unity Catalog securables named `system.ai.<model-name>` (e.g. `system.ai.claude-sonnet-4-5`, `system.ai.gpt-5-6-sol`, `system.ai.glm-5-2`) — and they are queried through `https://<workspace-url>/ai-gateway/...` routes. The older per-workspace **serving endpoints** named `databricks-<model>` (e.g. `databricks-claude-sonnet-4-6`, `databricks-deepseek-v4-1-flash`) still exist and are queried through `https://<workspace-url>/serving-endpoints/...`. Both coexist; a harness should support both URL families.
- The 2025-era catalogue the assignment names (DeepSeek V3.x/R1, Kimi K2, Qwen3, GLM-4.x) has rolled forward. The pay-per-token table on 2026-09-22 lists DeepSeek V4.x, Kimi K3, GLM-5.2/5.3, Qwen3.5/Qwen3-Next, Llama 4 Maverick + Llama 3.3 70B / 3.1 8B, Gemma 3 12B, GPT-6/5.x, Claude 4.x/5.x/Fable, Gemini 3.x, Grok 4.6 and a Databricks model called "Inkling". No DeepSeek V3/R1, Kimi K2 or GLM-4.x endpoint appeared in the extracted table (see Gaps).

## KQ1. Endpoint shapes, auth, and which shape supports which parameters

### Takeaway
There are three URL families: (a) Databricks-native `POST /serving-endpoints/<name>/invocations`, (b) OpenAI-compatible `https://<ws>/serving-endpoints` used as an SDK `base_url` with `model=<endpoint name>` (`/chat/completions`, `/embeddings`, `/completions`, `/responses`), plus a pay-per-token Anthropic route `https://<ws>/serving-endpoints/anthropic/v1/messages`, and (c) Unity Gateway model-service routes under `https://<ws>/ai-gateway/...` (`/ai-gateway/mlflow/v1/chat/completions`, `/ai-gateway/mlflow/v1/responses`, `/ai-gateway/openai/v1/responses`, `/ai-gateway/anthropic/v1/messages`, `/ai-gateway/gemini/...`, plus agent-specific `/ai-gateway/codex/v1` and `/ai-gateway/cursor/v1`). All take `Authorization: Bearer <PAT or OAuth token>`; the chat-completions schema supports `stream`, `tools` (max 32), `tool_choice` (`auto`/`required`/`none`), `response_format` (`text`/`json_schema`/`json_object`), `reasoning_effort`, `stop`, `top_k`, `logprobs`, `stream_options.include_usage`, while `n` is provisioned-throughput-only and unsupported parameters return HTTP 400 rather than being ignored.

### Cited Findings

Databricks-native and OpenAI-compatible (serving endpoints):
- Six query methods are documented; the REST one is `POST /serving-endpoints/{name}/invocations`; the OpenAI client path uses the `databricks-openai` package (`pip install -U databricks-openai`) and "Specifies endpoint name via the `model` parameter"; auth options are PATs (testing), service-principal tokens, and M2M OAuth ("security best practice for production") — [Use foundation models](https://docs.databricks.com/aws/en/machine-learning/model-serving/score-foundation-models)
- OpenAI client configuration example from the external-models tutorial: `client = OpenAI(api_key="dapi-your-databricks-token", base_url="https://example.staging.cloud.databricks.com/serving-endpoints")`; "All external models served through Model Serving are queried using the OpenAI-compatible API" — [External model endpoints tutorial](https://docs.databricks.com/aws/en/machine-learning/foundation-models/external-models-tutorial)
- Chat-model example uses `from databricks_openai import DatabricksOpenAI; client = DatabricksOpenAI(); client.chat.completions.create(model="system.ai.claude-sonnet-4-5", ...)` and shows a REST response shaped `{"model": "databricks-claude-sonnet-4-5", "choices": [{"message": {}, "index": 0, "finish_reason": null}], "usage": {"prompt_tokens": 7, "completion_tokens": 74, "total_tokens": 81}, "object": "chat.completion"}`; "For external models, you can include additional parameters that are valid for a given provider and endpoint configuration." — [Query a chat model](https://docs.databricks.com/aws/en/machine-learning/model-serving/query-chat-models)
- OpenAI Responses API: REST path `https://<workspace_host>.databricks.com/serving-endpoints/responses`; works with Databricks-hosted `databricks-gpt-6-*`, `databricks-gpt-5-*` and external OpenAI/Azure OpenAI; pay-per-token rejects `background`, `store`, `previous_response_id` ("return a 400 error if specified"); `service_tier` accepts only `"priority"` or `"default"`; supports `max_output_tokens`, text+image inputs, tools `function`, `custom`, `apply_patch`, `shell`, `image_generation`, `mcp`, `web_search` — [Query with the OpenAI Responses API](https://docs.databricks.com/aws/en/machine-learning/model-serving/query-openai-responses)
- Anthropic Messages on pay-per-token endpoints: `https://<workspace_host>.databricks.com/serving-endpoints/anthropic/v1/messages`; Python `anthropic.Anthropic(api_key="unused", base_url="https://<ws>/serving-endpoints/anthropic", default_headers={"Authorization": f"Bearer {DATABRICKS_TOKEN}"})`; curl `curl -u token:$DATABRICKS_TOKEN ... -d '{"model":"databricks-claude-sonnet-4-5","max_tokens":256,"messages":[...]}' https://<ws>/serving-endpoints/anthropic/v1/messages`; "The Anthropic Messages API is only compatible with Anthropic pay per token foundation models" (page last updated 2026-09-22) — [Query with the Anthropic Messages API](https://docs.databricks.com/aws/en/machine-learning/model-serving/query-anthropic-messages)

Unity Gateway model-service routes:
- Unified APIs: `/ai-gateway/mlflow/v1/chat/completions`, `/ai-gateway/mlflow/v1/embeddings`, `/ai-gateway/mlflow/v1/responses` ("Supervisor API", OpenResponses-compatible, Beta). Native provider APIs: `/ai-gateway/openai/v1/responses`, `/ai-gateway/anthropic/v1/messages`, `/ai-gateway/gemini/v1beta/models/{model-service}:generateContent`. Model names are fully qualified `system.ai.<model-name>`; auth is `Authorization: Bearer {DATABRICKS_TOKEN}`; base URL pattern `https://<workspace-url>/ai-gateway/{service}/v1`; supported SDKs: OpenAI Python SDK (MLflow + OpenAI routes), Anthropic Python SDK, Google GenAI; entitlement "Workspace access" or "Consumer access" (with the "Consumer access to Unity Gateway" preview) — [Query model APIs (model services)](https://docs.databricks.com/aws/en/ai-gateway/query-model-services)
- Optional request tagging header `Databricks-Ai-Gateway-Request-Tags` (JSON object of string key/values) is logged to the `request_tags` column of usage-tracking and inference tables — [Query model APIs (model services)](https://docs.databricks.com/aws/en/ai-gateway/query-model-services)
- A model service is "a Unity Catalog securable object ... that represents a governed LLM endpoint", lives centrally in UC rather than per workspace, can reference multiple destinations (Databricks-served or external provider services) with routing and fallback; privileges: `EXECUTE` to query, `MANAGE` to modify, `USE CATALOG`/`USE SCHEMA` always; queries run with "definer's privileges" (owner's, not caller's); "Discovering model services with only the `BROWSE` privilege" is not supported — [Model services](https://docs.databricks.com/aws/en/ai-gateway/model-services)
- Agent-specific gateway bases documented for manual setup: Claude Code `https://<workspace-url>/ai-gateway/anthropic`; Codex `<workspace-url>/ai-gateway/codex/v1` with `wire_api = "responses"`; Cursor `https://<workspace-url>/ai-gateway/cursor/v1`; Gemini CLI `https://<workspace-url>/ai-gateway/gemini`; OpenCode `<workspace-url>/ai-gateway/mlflow/v1` — [Integrate with coding agents (Azure Databricks, ms.date 2026-09-11)](https://learn.microsoft.com/en-us/azure/databricks/ai-gateway/coding-agent-integration-model-services)
- Bring-your-own Claude subscription flow uses two credentials: the user's Anthropic OAuth token in `Authorization`, and a Databricks OAuth token in `X-Databricks-AI-Gateway-Token`, plus `Databricks-Model-Provider-Service: <catalog>.<schema>.<name>`; `ANTHROPIC_BASE_URL="https://<workspace-url>/ai-gateway/anthropic"`; the Databricks token can come from `databricks auth token --host` (OAuth U2M) or a PAT — [Claude Max and Anthropic Enterprise support](https://docs.databricks.com/aws/en/ai-gateway/claude-max-anthropic-enterprise-support)

Chat-completions request schema (Foundation Model REST API reference):
- `messages` required; `max_tokens` default `null`; `stream` default `true` for chat (documented as "Stream responses back to a client...using Server-sent events") and `false` for Responses; `temperature` 1.0 in [0,2]; `top_p` 1.0; `top_k` null; `stop` `[]` string or list; `n` "Only available for provisioned throughput endpoints"; `tool_choice` defaults `"none"` without tools / `"auto"` with tools, supports `"auto"`, `"required"`, `"none"` or a ToolChoiceObject; `tools` "A max of 32 functions are supported"; `response_format` types `text`, `json_schema`, `json_object`; `logprobs` false; `top_logprobs` 0-20; `reasoning_effort` in `"minimal"`, `"low"`, `"medium"`, `"high"`, `"xhigh"`, `"max"`, `"none"`; `service_tier` `"default"`/`"priority"`; `use_raw_prompt` defaults "true for provisioned throughput, false for pay-per-token" — [Foundation model REST API reference](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference)
- Messages: `role` in `system`/`user`/`assistant`/`tool`; assistant `tool_calls` list; tool messages carry `tool_call_id`; "The `system` role can only be used once, as the first message in a conversation" — [API reference](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference)
- Response: `{id, choices[], object: "chat.completions", created, model, usage, service_tier}`; choice `extra_fields` ("safetyRating is the only extra field supported"); `usage` has `completion_tokens`, `prompt_tokens`, `total_tokens`, `reasoning_tokens` ("only applicable to reasoning models"), and `cache_read_input_tokens` / `cache_creation_input_tokens` as "top-level usage field for Databricks-hosted Claude endpoints" — [API reference](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference)
- Streaming: `text/event-stream`, chunk `object: "chat.completion.chunk"`, "only first chunk guaranteed to have `role`", `finish_reason` only on last chunk; `StreamOptions` `{"include_usage": bool}` "to include token usage in streams"; usage "Might not be present on streaming responses" — [API reference](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference)
- Parallel tool calls: `parallel_tool_calls` was not present in the extracted schema (see Gaps).
- Claude Sonnet 5 on Databricks: requests including `temperature`, `top_p` or `top_k` "return a 400 error" — [Supported models](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/supported-models); the same page says "No temperature/top_p/top_k sampling" for `databricks-claude-sonnet-5`.
- Older community report of the 400 shape for an unknown field: `BadRequestError ... error_code 'BAD_REQUEST' ... 'Bad request: json: unknown field "tool_choice"'` — [Databricks Community 66927](https://community.databricks.com/t5/generative-ai/trouble-using-foundation-models-api-with-instructor/td-p/66927)
- Serving-endpoint REST resources: `GET /api/2.0/serving-endpoints`, `GET /api/2.0/serving-endpoints/{name}`, `GET /api/2.0/serving-endpoints/{name}/openapi`, API scope `model-serving` — [Serving endpoints API: list](https://docs.databricks.com/api/workspace/servingendpoints/list)

### Inferences
- For a harness, the most portable target is the OpenAI-compatible surface: `base_url=https://<ws>/serving-endpoints` with `model=databricks-<x>` (per-workspace endpoints) or `base_url=https://<ws>/ai-gateway/mlflow/v1` with `model=system.ai.<x>` (governed model services). Same wire format, different model namespace; a harness should treat the (base URL, model-name style) pair as one "profile".
- Because `stream` is documented as defaulting to `true` for chat completions, a harness must always send `stream` explicitly (both values) rather than relying on OpenAI's `false` default. (This default contradicts OpenAI's convention; verify empirically before relying on it.)
- The "single system message, first position" rule means Claude-Code-style harnesses that emit several `system` messages (or a late system message) must merge them into one leading system message before sending.
- The `/serving-endpoints/anthropic` route being "only compatible with Anthropic pay per token foundation models" means an Anthropic-wire harness cannot use it to reach DeepSeek/Kimi/GLM; for those, speak OpenAI chat completions (`/serving-endpoints` or `/ai-gateway/mlflow/v1`).
- `X-Databricks-AI-Gateway-Token` + `Databricks-Model-Provider-Service` appear only in the BYO-subscription (model provider service) flow; for Databricks-billed models a plain `Authorization: Bearer <PAT>` is sufficient.

### Gaps
- `parallel_tool_calls`, `stream_options` on the native invocations route, `metadata`, `seed`, `logit_bias`, image `content` item types and `stop` semantics per model were not visible in the schema extract; unsupported ones will presumably 400 (Databricks documents 400 for unsupported parameters) but no per-parameter list was found.
- Whether `model` may be omitted on `POST /serving-endpoints/<name>/invocations` is not stated on the fetched pages (the endpoint name is in the URL; the OpenAI-compatible route requires `model`).
- Whether `/serving-endpoints/anthropic/v1/messages` and `/ai-gateway/anthropic/v1/messages` accept `tools`, `thinking`, `cache_control`, `count_tokens` and beta headers is not documented on the fetched page (it shows only `model`, `max_tokens`, `messages`, text+image). Claude Code is officially pointed at `/ai-gateway/anthropic`, which implies tools/streaming work there, but that is inference.

### Inferences
- A harness needs two reasoning decoders: (1) content-block style (`type: "reasoning"` with `summary[].text` and a `signature`) — used by Claude/GPT/Gemini on the FMAPI route; (2) top-level `reasoning_content` on `message`/`delta` for DeepSeek/Kimi/GLM/Grok. Preserve whichever came back and replay it on the assistant turn (Databricks says to pass the full assistant message; the Chinese-model vendors require `reasoning_content` back).
- GLM-5.3 and Qwen3.5 "always reason" and GLM-5.3 rejects `reasoning_effort: "none"`, so a harness must not send `none` blindly; DeepSeek V4.1 Flash defaults to `max` effort, which will inflate latency/cost unless the harness sets a lower effort.
- The "always reasons" + 1M-context open models are the natural substitutes for the assignment's DeepSeek V3.2/Kimi K2/GLM-4.x targets.

### Gaps
- No DeepSeek V3.x/R1, Kimi K2.x or GLM-4.x pay-per-token endpoints were present in the extracted table; whether they survive on provisioned throughput via `system.ai` is unverified.
- Exact context windows / max output tokens for DeepSeek V4.x, Kimi K3 (beyond "1M"), Qwen3-Next and GLM were not in the extract; the doc defers to provider values for GPT/Gemini/Claude.
- Region availability per open model was not captured (the overview page has region-by-region tables for `ap-*`, `ca-central-1`, `eu-*`, and presumably `us-*`, but they were not extracted).
- "ADI Services" (Azure) was not expanded/defined on the fetched pages.
- Whether Databricks emits `reasoning_content` for GLM 5.3 natively or only on a Fireworks-backed test endpoint is ambiguous in the LiteLLM PR summary.

## KQ3. Error formats (400/429/5xx), context-length and max_tokens wording, rate-limit headers, mid-stream errors

### Takeaway
Two error envelopes coexist: the classic Databricks REST shape `{"error_code": "BAD_REQUEST", "message": "..."}` (seen for unknown fields) and an OpenAI-style 429 body `{"error": {"message": "Rate limit exceeded: ...", "type": "rate_limit_exceeded", "code": 429, "limit_type": "input_tokens_per_minute", "limit": ..., "current": ..., "retry_after": ...}}`; Databricks pre-admits requests against `max_tokens` (an over-budget `max_tokens` is rejected immediately with 429 and unused tokens are credited back), and requests over 4 MB fail as a TLS EOF, not a clean HTTP error.

### Cited Findings
- Rate-limit 429 body: `{"error": {"message": "Rate limit exceeded: [limit type]", "type": "rate_limit_exceeded", "code": 429, "limit_type": "input_tokens_per_minute", "limit": 200000, "current": 200150, "retry_after": 15}}`; `limit_type` is one of ITPM, OTPM, QPS, QPH — [FMAPI limits and quotas](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/limits)
- Pre-admission: "if `max_tokens` would cause you to exceed OTPM limits, Databricks immediately rejects requests with a 429 error"; "if the actual token usage is less than the reserved `max_tokens`, Databricks credits the difference back to your rate limit allowance" — [FMAPI limits](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/limits)
- Claude Sonnet 4 "Defaults to 1,000 output tokens when `max_tokens` is unspecified, returning finish reason `length` when reached" — [FMAPI limits](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/limits)
- 400 for unsupported parameters: Responses API `background`/`store`/`previous_response_id` "return a 400 error if specified" — [Query with the OpenAI Responses API](https://docs.databricks.com/aws/en/machine-learning/model-serving/query-openai-responses); Claude Sonnet 5 sampling params return 400 — [Supported models](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/supported-models)
- Unknown-field 400 example: `error_code 'BAD_REQUEST'`, message `Bad request: json: unknown field "tool_choice"` — [Databricks Community 66927](https://community.databricks.com/t5/generative-ai/trouble-using-foundation-models-api-with-instructor/td-p/66927)
- Responses API error object fields: `code`, `message`, `param`, `type`, surfaced in the response's `error` field — [API reference](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference)
- Payload limit 4 MB per request for foundation-model endpoints; request/response logging threshold 1 MB; max execution 597 seconds; workspace QPS cap 200; overhead latency under 50 ms — [FMAPI limits](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/limits)
- Oversized payloads surface as `SSLEOFError(8, 'EOF occurred in violation of protocol')` on `/serving-endpoints/<name>/invocations`; root cause is "the request payload exceeds the maximum size limits" (16 MB custom models / 4 MB foundation-model endpoints); fix is to shrink or split the payload (KB dated 2025-05-23) — [Databricks KB: SSL error when invoking model serving endpoint](https://kb.databricks.com/en_US/machine-learning/ssl-error-when-invoking-databricks-model-serving-endpoint)
- Client-side timeouts show as "timed out" or 4xx Bad Request — [Debug model serving timeouts](https://docs.databricks.com/aws/en/machine-learning/model-serving/model-serving-timeouts)
- Gateway fallback triggers: "If initial request returns 429 or 5XX error, request falls back" — [Configure governance on model serving endpoints (legacy)](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints)

### Inferences
- A harness should parse both envelopes: check `body.error_code`/`body.message` first, then `body.error.{type,code,limit_type,retry_after}`; honour `retry_after` (seconds) from the JSON body since no `Retry-After` HTTP header is documented.
- Because a large `max_tokens` can itself trigger 429 (pre-admission), Claude-Code-style harnesses that request 32K–64K output tokens per turn may be rejected under the 20,000 OTPM standard-tier limit; set `max_tokens` conservatively or use provisioned throughput (no TPM limits).
- Keep every request comfortably under 4 MB; a TLS EOF is otherwise indistinguishable from a network failure, and retrying it is pointless.

### Gaps
- No Databricks-authored wording for a context-length-exceeded 400 was found. (A search hit with "This endpoint's maximum context length is 262144 tokens. However, you requested about 504212 tokens" is OpenRouter's wording, not Databricks'.) Likewise no verified wording for a "max_tokens exceeds the model limit" error.
- No documentation of rate-limit HTTP headers (`x-ratelimit-*`, `Retry-After`) was found.
- How errors appear mid-stream (SSE `error` event vs terminating the stream) is not documented on any fetched page.
- The HTTP status/JSON returned when an AI Gateway guardrail blocks a request was not documented.

## KQ5. AI (Unity) Gateway features relevant to a harness: usage tracking, guardrails, rate limits, fallbacks, prompt caching, `x-databricks-use-coding-agent-mode`, payload logging

### Takeaway
Unity Gateway gives usage tracking in `system.serving.endpoint_usage`, inference (payload) tables with less-than-1-hour delay (payloads over 1 MiB dropped, streamed responses aggregated), guardrails (safety; PII "Block" or "Mask"; output guardrails not applied to streaming), QPM/TPM rate limits per endpoint/user/service principal/group (max 20, 5 group-specific), and 429/5xx-triggered fallbacks (max two, external models only). `x-databricks-use-coding-agent-mode: true` is documented only as a required custom header in the Claude Code config; its semantics are undocumented.

### Cited Findings
- Coding-agent integration "provides rate limiting, usage tracking, and inference tables—with all controls configured at the model service, user, or group level"; built-in usage dashboard has a "Coding Agents" tab — [Integrate with coding agents (Azure)](https://learn.microsoft.com/en-us/azure/databricks/ai-gateway/coding-agent-integration-model-services)
- `system.serving.endpoint_usage` "captures token counts for each request" with `input_token_count`, `output_token_count`, `input_character_count`, `output_character_count`, `request_time`, `status_code`, `served_entity_id`, `usage_context`; tokens are "estimated as (`text_length`+1)/4 if the token count is not returned" — [Configure governance (legacy)](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints)
- Inference tables: data lands "less than an hour after querying the endpoint"; "Payloads larger than 1 MiB are not logged"; "Streaming is supported. In streaming scenarios, the response payload aggregates" — [Configure governance (legacy)](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints)
- Guardrails: safety filter; PII detection with "Block" or "Mask"; "Output guardrails are not supported for embeddings models or for streaming" — [Configure governance (legacy)](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints)
- Rate limits: QPM or TPM; scopes endpoint, user (default), individual users/service principals, user groups; "Maximum of 20 rate limits and up to 5 group-specific rate limits"; "Endpoint rate limit is a global maximum. If exceeded, all requests blocked"; "TPM rate limits cannot be applied to serving endpoints that serve custom models" — [Configure governance (legacy)](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints)
- Fallbacks: trigger on 429 or 5XX; "Maximum of two fallbacks"; "Each entity tried once in sequential order until success"; "First successful or last failed request logged to usage/payload tables"; "Only supported for external models" — [Configure governance (legacy)](https://docs.databricks.com/aws/en/ai-gateway/configure-ai-gateway-endpoints)
- Model-service routing: "When a model service routes to a model provider service destination, only the model service's Unity AI Gateway features (such as rate limits, guardrails, inference tables, and fallbacks) apply, while any Unity AI Gateway features configured on the model provider service itself are skipped"; `ai_query` batch inference gets only usage tracking — [Query model APIs](https://docs.databricks.com/aws/en/ai-gateway/query-model-services)
- Budgets: `ug usage` "shows spending and budget consumption"; usage summary for last 7 days — [Get started with coding agents](https://docs.databricks.com/aws/en/ai-gateway/coding-agent-integration-model-services)
- Prompt caching: usage returns `cache_read_input_tokens` / `cache_creation_input_tokens` for Databricks-hosted Claude endpoints — [API reference](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/api-reference); the official Claude Code config sets `"ENABLE_PROMPT_CACHING_1H": "1"` and `"ENABLE_TOOL_SEARCH": "1"` alongside the gateway settings — [Integrate with coding agents (Azure)](https://learn.microsoft.com/en-us/azure/databricks/ai-gateway/coding-agent-integration-model-services); GPT-5.5/5.5 Pro list "extended prompt caching" — [Supported models](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/supported-models)
- `x-databricks-use-coding-agent-mode: true` is the documented value of `ANTHROPIC_CUSTOM_HEADERS` in the Claude Code manual setup, together with `"CLAUDE_CODE_USE_GATEWAY": "1"` — [Integrate with coding agents (Azure)](https://learn.microsoft.com/en-us/azure/databricks/ai-gateway/coding-agent-integration-model-services); a GitHub-wide search found no repository documenting the header's behaviour — [search results](https://github.com/databricks/databricks-agent-skills)
- Request tags: `Databricks-Ai-Gateway-Request-Tags` header → `request_tags` column — [Query model APIs](https://docs.databricks.com/aws/en/ai-gateway/query-model-services)
- Telemetry: coding agents can export OpenTelemetry metrics/logs to UC Delta tables via `https://<workspace-url>/api/2.0/otel/v1/metrics` and `/api/2.0/otel/v1/logs` with headers `Authorization=Bearer <pat>` and `X-Databricks-UC-Table-Name=<catalog>.<schema>.<table>`; Claude Code needs `"CLAUDE_CODE_ENABLE_TELEMETRY": "1"`; data appears within 5 minutes — [Integrate with coding agents (Azure)](https://learn.microsoft.com/en-us/azure/databricks/ai-gateway/coding-agent-integration-model-services)
- Legacy per-endpoint config surface: `ai_gateway` block (inference tables, rate limits, guardrails) on the serving endpoint — [Serving endpoints API](https://docs.databricks.com/api/workspace/servingendpoints/list)

### Inferences
- Guardrail "Block" mode implies a rejected request (an error response), "Mask" implies a modified payload; since output guardrails are skipped for streaming, a streaming harness sees only input-side blocking/masking. Exact error shape unknown (Gap).
- `x-databricks-use-coding-agent-mode` most plausibly flags traffic for the "Coding Agents" dashboard tab/usage attribution and/or enables Claude-Code-specific handling (e.g. the 1-hour cache, tool search); a harness mimicking Claude Code should send it, and it is harmless to send elsewhere. Unverified.
- Because inference tables drop payloads over 1 MiB and aggregate streams, do not rely on them for exact replay of large agent turns.

## KQ7. Deploying an open model not in the pay-per-token catalogue on provisioned throughput

### Takeaway
Pre-registered open models live in Unity Catalog `system.ai`; you serve one from Catalog Explorer ("Serve this model") or by `POST /api/2.0/serving-endpoints` with `served_entities[{entity_name, entity_version}]` plus either `min_provisioned_throughput`/`max_provisioned_throughput` (throughput-band models) or `provisioned_model_units` via `/api/2.0/serving-endpoints/pt` (model-unit models); on-demand PT has no term commitment, no TPM limits, up to 200 QPS per workspace, and per-model output caps (GPT OSS 25,000; Gemma 3 12B and Llama 8,192).

### Cited Findings
- "You can find these models under the catalog `system` in the schema `ai` (`system.ai`)"; UI: select the model, click **Serve this model**, choose tokens/sec in the "Up to" dropdown; REST: throughput-band models use `min_provisioned_throughput` and `max_provisioned_throughput` on `/api/2.0/serving-endpoints`; model-unit models use `provisioned_model_units` on `/api/2.0/serving-endpoints/pt`; both use `served_entities` with `entity_name`, `entity_version`; "On-demand provisioned throughput has no term commitment. You pay for the capacity you allocate and can change or remove it at any time"; only Llama **Instruct** variants supported (not base) — [On-demand provisioned throughput](https://docs.databricks.com/aws/en/machine-learning/foundation-model-apis/deploy-prov-throughput-foundation-model-apis)

- Meta Llama 4 Maverick "Available for provisioned throughput in Public Preview" (2026-09-22) — [Foundation model overview](https://docs.databricks.com/aws/en/machine-learning/model-serving/foundation-model-overview)

## KQ8. VPN / network access patterns (IP allow-listing, proxies, CA bundles)

### Takeaway
Serving and gateway routes share the workspace hostname, so workspace IP access lists (corporate egress/VPN IPs) and PrivateLink govern them; IP access lists do not filter PrivateLink traffic, and the only "SSL error" Databricks documents for endpoint invocation is really the 4 MB payload limit, not a certificate problem.

### Cited Findings
- Workspace IP access lists control access to "the workspace or workspace-level APIs" and let you "Allow connections only from approved networks like corporate offices or VPNs"; "If you use PrivateLink, IP access lists apply only to requests over the internet (public IP addresses). Private IP addresses from PrivateLink traffic cannot be blocked by IP access lists" — [IP access lists](https://docs.databricks.com/aws/en/security/network/front-end/ip-access-list)
- Inbound PrivateLink routes traffic "through a VPC interface endpoint instead of the public internet"; corporate DNS can forward Databricks domains to a Route 53 inbound resolver — [Configure inbound PrivateLink](https://docs.databricks.com/aws/en/security/network/front-end/front-end-private-connect), [PrivateLink DNS](https://docs.databricks.com/aws/en/security/network/classic/privatelink-dns)
- Network policies can "restrict access based on identity, request type, and network source", allowing "trusted public sources (for example, static corporate IPs), while still using Private Link" — [Private connectivity to AWS-managed resources](https://docs.databricks.com/aws/en/security/network/serverless-network-security/pl-aws-resources)
- `SSLEOFError ... /serving-endpoints/<name>/invocations` is caused by payloads above 4 MB (foundation models) / 16 MB (custom), not by proxies or CA bundles — [Databricks KB](https://kb.databricks.com/en_US/machine-learning/ssl-error-when-invoking-databricks-model-serving-endpoint)
- Endpoint hostnames used in docs: `https://<workspace_host>.databricks.com/...` and `https://example.staging.cloud.databricks.com/...`; Unity Gateway requires a workspace in a "Unity Gateway supported region" — [Integrate with coding agents (Azure)](https://learn.microsoft.com/en-us/azure/databricks/ai-gateway/coding-agent-integration-model-services)

### Inferences
- A harness only needs standard HTTPS egress to the workspace host (or its PrivateLink alias); if the corporate proxy does TLS inspection, standard Python/Node CA overrides (`REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS`) apply — nothing Databricks-specific was found, so this is generic guidance, not a Databricks fact.
- Long agent turns can approach the 597-second execution cap; corporate proxies with shorter idle timeouts will cut streams first — prefer streaming with keepalives.

### Gaps
- No Databricks documentation on proxy configuration or custom CA bundles for endpoint clients was found.
- The exact error returned when an IP access list blocks a serving request (status code/JSON) was not documented on the fetched page.
- Per-region availability of Unity Gateway (feature-region-support table) was not extracted.
