# Copy OpenCode's mechanics, keep Claude Code's shell

OpenCode (`anomalyco/opencode`, formerly `sst/opencode`) is, as of 2026-09-24, a fully agentic, tool-executing coding harness: its `runLoop` is a `while (true)` over Vercel AI SDK `streamText` with `maxSteps = agent.steps ?? Infinity`, tool calls execute concurrently as they stream in, results are fed back as tool parts, context overflow triggers auto-compaction mid-loop, and provider errors are retried up to five times around the whole stream ([prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts), [processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts), [retry.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/retry.ts)). It is MIT, **~210k stars, 75% TypeScript on Bun with Effect services, zero Go** (the Bubble Tea TUI died in v1.0.0 on 2025-10-31, replaced by OpenTUI's Zig renderer + SolidJS), ships **v1.18.32 (2026-09-21)** at a cadence of ten releases in four weeks, and is architected server-first: TUI, `run`, web, desktop, IDE plugins and ACP are all clients of one Hono HTTP/SSE server ([README](https://github.com/anomalyco/opencode), [languages API](https://api.github.com/repos/anomalyco/opencode/languages), [v1.0.0](https://github.com/anomalyco/opencode/releases/tag/v1.0.0), [releases](https://github.com/anomalyco/opencode/releases), [server docs](https://opencode.ai/docs/server/)). For rolo-claude the verdict splits cleanly along one line: **adopt OpenCode's mechanical reliability rules** (the 9-strategy edit replacer with its 0.65 Levenshtein and 50 %-lines thresholds, the hidden `invalid` tool, the 2000-line/50 KB truncation-to-file, the retry classifier and its jittered 2 s × 2ⁿ backoff, the overflow regex list, the `usable = limit − reserved` compaction gate with 40k/20k prune constants and the five-heading summary, the per-model transform table, `interleaved.field` reasoning replay) because they are provider-agnostic string and state-machine code that ports to Python verbatim; **adapt its UX ideas** (remappable leader-key keymap, `ctrl+p` palette, git-shadow `/undo`, child-session navigation, `system` theme) onto Claude Code's own file formats; and **avoid its surfaces and traps** (server-first attach, share links, JS plugins, SQLite-as-truth whose migration lost sessions, the hard 32k output cap that misclassifies truncation, a doom-loop guard that only inspects the current message and is silently auto-approved under `--auto`, the lossy `--format json`). Two corrections to the earlier reports follow from the code: OpenCode contains **no Qwen temperature at all** (the "0.55" attributed to it does not exist in `transform.ts`; Qwen falls through to the provider default), and it has **no headed-summary retry and no `finish_reason: length` auto-continue**, so those remain rolo-claude's own design choices, not borrowed ones ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts), [compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)). Everything below is sized against the remaining milestones H4–H9/U5 and against what already exists in `rolo_claude/` today; the appendix carries the exact rules a worker can implement without reopening the sources.

## OpenCode runs an unbounded concurrent tool loop on a server-first core

The loop is structurally the same state machine as Claude Code's, which is why its mechanisms port rather than its framework. Each user prompt starts `runLoop`; every iteration sets the session busy, assembles the system prompt from the provider-family prompt file, an `<env>` block ("Working directory", "Workspace root folder", "Is directory a git repo", "Platform", "Today's date"), the instruction files, `<mcp_instructions>` and the skills list, then calls `streamText` with the frozen tool set, `activeTools` filtered to exclude `invalid`, and **`maxRetries: 0`** so that OpenCode's own retry policy, not the SDK's, governs failures ([prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts), [system.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/system.ts), [llm.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm.ts)). The processor maps the SDK's `fullStream` one-to-one onto text, reasoning, tool-input, tool-call, tool-result, tool-error, step-start and step-finish events; each `tool-call` runs immediately in its own fiber tracked by a `Deferred`, so **tool calls execute in parallel as they arrive** rather than after the assistant message completes, and the loop only ends when the last assistant message finished with a reason other than `tool-calls`/`unknown` and contains no tool parts ([processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts), [prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)). Three details matter for a port. A `stop` finish that nevertheless carries tool calls keeps the loop running (the code comments that "some providers return stop even when the assistant message contains tool calls"); `content-filter` surfaces as an error; and **`length` has no branch at all** — truncation is caught only indirectly by the token-overflow check after `step-finish`, which is exactly why issue #18108 documents `finishReason: "length"` being "treated as normal completion" and truncated `write()` JSON being "misclassified as invalid tool calls" ([prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts), [#18108](https://github.com/anomalyco/opencode/issues/18108)). There is likewise no empty-response retry and no synthetic message for a step that returns neither text nor tools ([prompt.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)). rolo-claude already handles both cases (`classify_length_tool_call` returns `"length"` → an error result telling the model to split the operation; `is_retryable_empty_completion` retries once), so on these two points the Python harness is ahead and should not regress toward OpenCode.

Step limits and interruption are handled by text, not by exceptions. When an agent's `steps` cap is reached, OpenCode injects `MAX_STEPS_PROMPT` — "CRITICAL - MAXIMUM STEPS REACHED … Tools are disabled until next user input. Respond with text only" with a required summary/remaining-tasks/recommendations structure — so the model closes cleanly instead of dying on a dead tool call ([max-steps.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/runner/max-steps.ts), [agents docs](https://opencode.ai/docs/agents/)). Aborts stamp the assistant message with an `AbortError` and, on replay, any tool part still `pending`/`running` becomes an `output-error` whose text is **`[Tool execution was interrupted]`**, while pruned outputs replay as **`[Old tool result content cleared]`** — cheap, proven strings that keep every provider's tool-call/tool-result pairing valid after aborts and pruning ([message-v2.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/message-v2.ts)). Sub-tasks are child sessions created with `parentID`, fresh context, a derived permission set and a title suffix `(@name subagent)`, and the `task` tool returns `<task id="…" state="…"><task_result>…</task_result></task>` plus a resumable `task_id` ([task.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/task.ts), [changelog](https://opencode.ai/changelog)).

Architecturally OpenCode is a headless server first. `opencode serve` exposes an OpenAPI 3.1 document at `/doc`, SSE on `/event`/`/global/event`, basic auth via `OPENCODE_SERVER_PASSWORD`, and endpoints for sessions, messages, `prompt_async`, permissions, shell, files, config, agents and even TUI control (`/tui/submit-prompt`, `/tui/append-prompt`); the interactive `opencode` binary starts TUI and server together, `opencode run` drives the same code through an in-process fetch handler, and `--attach` points any client at a remote server ([server docs](https://opencode.ai/docs/server/), [run.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/cli/cmd/run.ts)). The `@opencode-ai/sdk` package, ACP (`opencode acp`, JSON-RPC over stdio for Zed/JetBrains/Neovim), the web UI and the desktop app are all thin clients of that API ([SDK docs](https://opencode.ai/docs/sdk/), [ACP docs](https://opencode.ai/docs/acp/)). The one surface that is demonstrably weak is headless output: `--format json` emits `step_start`/`tool_use`/`text`/`step_finish`/`error` lines but **no text deltas, never echoes the user prompt, can exit before the final `step_finish`, and drops sub-agent parts** ([#38638](https://github.com/anomalyco/opencode/issues/38638), [#29997](https://github.com/anomalyco/opencode/issues/29997), [#26855](https://github.com/anomalyco/opencode/issues/26855), [#49300](https://github.com/anomalyco/opencode/issues/49300)). Two things rolo-claude cares about are simply absent: there is no mid-turn steering primitive (a prompt sent to a busy session queues via `prompt_async`, and `escape` is a hard `session_interrupt`), and there is no bidirectional stream-json input ([server docs](https://opencode.ai/docs/server/), [keybinds docs](https://opencode.ai/docs/keybinds/)). H4's steering design (cut at the next chunk, finish running tools, append as a user message, continue) is therefore ahead of OpenCode, and U0's Claude-Code-shaped `stream-json` with deltas and a user echo is precisely what OpenCode users file bugs asking for.

## Nine replacers, an `invalid` tool and 50 KB caps keep weak models alive

The tool registry is lowercase and deliberately small: `invalid`, `question` (only when the client is app/cli/desktop), `bash`, `read`, `glob`, `grep`, `edit`, `write`, `task`, `webfetch`, `todowrite`, `websearch` (only on OpenCode-hosted providers or with Exa/Parallel flags), `skill`, `apply_patch` (only for `gpt-*` models, where it replaces edit/write), `execute` (code-mode flag), `lsp` and `plan_exit` (experimental), plus MCP tools named `<server>_<tool>` and three MCP-resource helpers that appear only when a server exposes resources ([registry.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/registry.ts), [tools.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/tools.ts), [tools docs](https://opencode.ai/docs/tools/)). Every tool's output passes through one truncation service: **`MAX_LINES = 2000`, `MAX_BYTES = 50 * 1024`**, head (default) or tail, with the full text written to a file under a truncation directory and a notice that either tells an agent with task permission to "Use the Task tool to have explore agent process this file with Grep and Read" or tells everyone else to use Grep/Read with `offset`/`limit` on the saved file ([truncate.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/truncate.ts)). `read` defaults to 2000 lines, caps each line at 2000 characters with the suffix `... (line truncated to 2000 chars)`, caps the whole read at 50 KB, renders `<line>: <content>` inside `<path>`/`<type>`/`<content>` tags, returns images and PDFs as base64 attachments, and answers a missing path with up to three "Did you mean one of these?" suggestions ([read.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/read.ts)). `grep` and `glob` are ripgrep with a hard **limit of 100** results, `webfetch` caps responses at 5 MB with a 30 s default and 120 s maximum timeout and converts HTML through Turndown, and `bash` defaults to a **2-minute timeout**, takes an optional `workdir`, and returns `exit`, `truncated` and an `outputPath` when it spilled ([grep.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/grep.ts), [glob.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/glob.ts), [webfetch.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/webfetch.ts), [shell.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/shell.ts)). rolo-claude's `spill_and_truncate` already spills to `<session>/tool-results/<id>.txt` but keys on a 30 000-character cap with a 60/30 head/tail split; the OpenCode delta worth taking is the line cap, the "read the saved file with offset/limit" hint, and surfacing `outputPath` in the tool metadata.

The `edit` tool is the single most portable piece of OpenCode. Its parameters are Claude Code's (`filePath`, `oldString`, `newString`, `replaceAll`), but when the exact substring is absent it walks a **nine-stage replacer chain**: exact → line-trimmed → block-anchor (first/last lines as anchors, middle similarity by Levenshtein ≥ 0.65) → whitespace-normalised → indentation-flexible (common indent stripped) → escape-normalised (`\n`, `\t` unescaped) → trimmed-boundary → context-aware (≥ 50 % of middle lines must match) → multi-occurrence; and it refuses a fuzzy hit whose matched span is much larger than the request — **≥ `max(oldLines + 3, oldLines × 2)` lines or trimmed length > `max(len + 500, len × 4)`** — with the error "Refusing replacement because the matched span is much larger than oldString" ([edit.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/edit.ts)). The other errors are equally reusable ("Could not find oldString in the file. It must match exactly…", "Found multiple matches for oldString. Provide more surrounding context…", "No changes to apply: oldString and newString are identical."), CRLF is preserved, a unified diff is produced with `createTwoFilesPatch`, and LSP diagnostics are appended as "LSP errors detected in this file, please fix:" ([edit.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/edit.ts)). This matters because edit compliance is the measured weak point of open-weight models — Aider's leaderboard has Kimi K2 and Qwen3-235B at 92.9 % well-formed and Qwen3-32B at 83.6 %, and Qwen3-Coder via OpenRouter has delivered `oldString` as an object instead of a string ([polyglot leaderboard](https://raw.githubusercontent.com/Aider-AI/aider/main/aider/website/_data/polyglot_leaderboard.yml), [#6918](https://github.com/anomalyco/opencode/issues/6918)). rolo-claude's `tools/edit.py` today has two stages (exact, then per-line `strip()` window match with re-indentation) and a structured "0 near-matches / N near-matches" error; extending it to the full chain with OpenCode's thresholds and span guards is a pure-Python task with no new dependency.

The second reliability device is the **`invalid` pseudo-tool**. The SDK's `experimental_repairToolCall` hook first tries a case-insensitive rename (`Read` → `read`); failing that it rewrites the call to `toolName: "invalid"` with `input: {tool, error}`, and the `invalid` tool — description "Do not use", never listed in `activeTools` — returns "The arguments provided to the tool are invalid: ${error}" as an ordinary tool result, so a malformed or unknown call becomes something the model reads and corrects on the next step instead of a crashed turn ([llm.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm.ts), [invalid.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/invalid.ts)). Its limits are documented too: repair drops the required `tool` field for unnamed calls (#47831), and Kimi K2.7 on Together/Fireworks looped on `invalid` with "missing required keys" until the reporter gave up, closed not planned ([#47831](https://github.com/anomalyco/opencode/issues/47831), [#34071](https://github.com/anomalyco/opencode/issues/34071)). rolo-claude's `agent/repair.py` already does the equivalent with an alias table, case-insensitive match, difflib at ≥ 0.85 (never for `mcp__` names), argument coercion and a quoted error result; what it should copy is only the discipline that the error result is always a *tool result paired to the original `tool_use_id`*, never a stream error, and the wording. Tool schemas are sanitised per provider before being sent: Gemini gets string-coerced enums, `anyOf` for type arrays and `nullable`; OpenAI/Azure get boolean schemas turned into `{type: "string"}`, `const` into `enum` and an allow-listed keyword set ("Mirrors Codex's Rust JSON schema compatibility lowering"); **Moonshot/Kimi get `$ref` nodes stripped of sibling keywords and tuple-style `items` flattened to `items[0]`** because "Moonshot expands $ref before validation and rejects sibling keywords like description on the same node" ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts), [json-schema.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/json-schema.ts)); Kimi K2.5 additionally rejected `{}` parameter schemas without an explicit `"required": []` ([#11357](https://github.com/anomalyco/opencode/issues/11357)). Claude Code's built-in schemas are flat, but MCP servers ship `$ref`/`anyOf`-heavy schemas, so this belongs in rolo-claude's catalog freeze for MCP tools.

### Permissions are last-match triples, and `--auto` is exactly rolo-claude's auto mode

Permission is a ruleset of `{permission, pattern, action}` triples evaluated with `findLast` over the flattened rulesets — global config, agent overrides, session-scoped "always" approvals — and **the default when nothing matches is `ask`**; `ask()` iterates the requested patterns so that any `deny` wins immediately, all-`allow` skips the prompt, and anything else raises a prompt whose replies are `once`, `always` (pushes an in-memory allow rule per `always` pattern, never written to config) or `reject` (a `RejectedError`, or `CorrectedError({feedback})` when the user typed a message) ([permission/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/permission/index.ts), [permissions docs](https://opencode.ai/docs/permissions/)). Keys are `read`, `edit`, `glob`, `grep`, `bash`, `task`, `skill`, `lsp`, `question`, `webfetch`, `websearch`, `external_directory`, `doom_loop`; `Wildcard.match` escapes regex specials, maps `*` → `.*` and `?` → `.`, anchors, is case-insensitive on Windows, normalises backslashes, and makes a trailing `" *"` optional so `git *` also matches bare `git` ([wildcard.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/util/wildcard.ts)). The built-in agents supply the "most things allow" behaviour the docs describe: base rules are `doom_loop: ask`, `external_directory: {"*": ask}`, `question: deny`, `plan_enter`/`plan_exit: deny`, `*.env` read `ask`; `build` allows `question` and `plan_enter`; `plan` denies `edit` except `.opencode/plans/*.md`; `explore` allows only `grep`/`glob`/`read` ([agent.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/agent/agent.ts)). The docs' claim that `.env` is "denied" disagrees with the code's `ask`; the code is current.

Bash permission is where OpenCode invests real machinery: the command is parsed with **tree-sitter-bash** (or tree-sitter-powershell), `collect()` derives one pattern per sub-command so a `bash: {"git *": allow, "rm *": deny}` rule sees `git status && rm -rf x` as two checks, and any of `cd, rm, cp, mv, mkdir, touch, chmod, chown, cat` touching a path outside the worktree raises `external_directory` ([shell.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/shell.ts)). There is no OS sandbox at all — safety is permission rules plus that parse — which is the closest published design to rolo-claude's "no safety heuristics, only the user's own rules and hooks" decision. Headless behaviour is the exact model for rolo-claude's auto mode: `opencode run` answers every `permission.asked` with `once` under `--auto` and `reject` otherwise, and non-interactive sessions get a fixed ruleset denying `question`, `plan_enter` and `plan_exit` ([run.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/cli/cmd/run.ts)). The one trap is that `--auto` also auto-approves the `doom_loop` ask, so OpenCode's loop guard is off precisely in the mode where runaway loops cost the most; that is how a `deepseek-v4-flash` subagent ran **364 identical `grep` calls for ~50 minutes and ~142 M cache-read tokens** with, in the reporter's words, "no repeated-action detection, no step limit, no heartbeat timeout" ([#45442](https://github.com/anomalyco/opencode/issues/45442)). rolo-claude's breaker is a reliability mechanism, not a safety heuristic, and must stay armed in auto mode.

## The provider layer is a catalog plus 1,900 lines of transforms

OpenCode owns no HTTP client: each provider is a Vercel AI SDK package named by the config's `npm` field (default `@ai-sdk/openai-compatible`), instantiated as `factory({ name: providerID, ...options })` behind a wrapped `fetch` that combines the caller's signal with a **300 000 ms header timeout, a 300 000 ms chunk-idle timeout on `text/event-stream` bodies (`ProviderError.ResponseStreamError("SSE read timed out")`, classified retryable) and an optional total `timeout`**, forces `includeUsage` on chat-completions SDKs, substitutes `${VAR}` in base URLs, and merges per-model `headers` after the hard-coded `User-Agent: opencode/<ver>` so that per-model headers win ([provider.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts), [request.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm/request.ts), [config docs](https://opencode.ai/docs/config/)). Model metadata comes from **models.dev `api.json` (4.9 MB)** deep-merged with `opencode.json` overrides; the fields a harness needs are `limit{context,output,input?}`, `cost{input,output,cache_read,cache_write,reasoning?,context_over_200k}`, `reasoning`, `reasoning_options` (`toggle` / `effort` values / `budget_tokens`), **`interleaved{field}`** (which wire field carries reasoning: `reasoning_content` on DeepSeek/Moonshot/Z.ai direct, `reasoning_details` on OpenRouter re-listings) and **`temperature` (a boolean; `kimi-k3` is `false`)** ([models.dev api.json](https://models.dev/api.json), [config.json schema](https://opencode.ai/config.json)). The catalog already knows the hosts rolo-claude uses: `openrouter` (385 models, `@openrouter/ai-sdk-provider`), `deepseek` (`https://api.deepseek.com`), `moonshotai` (`https://api.moonshot.ai/v1`), `zai` and `zai-coding-plan`, `alibaba`/`alibaba-cn` (DashScope compatible-mode), `minimax` (served through the **Anthropic** dialect at `https://api.minimax.io/anthropic/v1`), and a `databricks` provider (`@ai-sdk/openai-compatible` at `https://${DATABRICKS_HOST}/ai-gateway/mlflow/v1`, env `DATABRICKS_HOST`+`DATABRICKS_TOKEN`, 30 models including `databricks-glm-5-2` and `databricks-kimi-k2-7-code`) ([models.dev api.json](https://models.dev/api.json)). Request parameters are merged in a fixed order — provider defaults → `model.options` → `agent.options` → the selected reasoning *variant* — with tools sorted alphabetically for cache stability and the system prompt collapsed to at most two messages so the two cache breakpoints cover it ([request.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm/request.ts)).

The family quirks live in `provider/transform.ts` and are keyed on model-id substrings. `temperature()` returns 1.0 for `glm-4.6`/`glm-4.7`/`minimax-m2`/Gemini 2.5+/`north-mini-code`, **0.6 for base Kimi K2 and 1.0 for K2 thinking/K2.5+**, `undefined` for Claude and for everything else — and it is only applied when the models.dev `temperature` flag is true; `topP()` gives 0.95 to Gemini, MiniMax-M2, Kimi K2.5+ and `deepseek-v4-flash`; `topK()` gives Gemini 64 and MiniMax-M2 20 or 40 ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)). `options()` sets `toolStreaming = false` for Vertex-Anthropic and for any `@ai-sdk/anthropic` model whose id lacks "claude", `store = false` for OpenAI-family SDKs, `usage: {include: true}` for OpenRouter, `thinking: {type: "enabled", clear_thinking: false}` for Z.ai, `enable_thinking: true` for DashScope reasoning models, `chat_template_args: {enable_thinking: true}` for Baseten-hosted Kimi/GLM, `prompt_cache_key`/`promptCacheKey = sessionID` for deepinfra/cerebras/openai/azure/xai/mistral/venice, and GPT-5 `reasoningEffort: "medium"` + `include: ["reasoning.encrypted_content"]` ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)). `normalizeMessages()` sanitises lone surrogates, scrubs Claude tool ids to `[a-zA-Z0-9_-]`, rewrites Mistral ids to nine alphanumerics and inserts an assistant `"Done."` between a tool message and a following user message, **appends `{type: "reasoning", text: ""}` to every DeepSeek assistant message that lacks one**, and for any model with `interleaved.field` (except the OpenRouter SDK, which replays `reasoning_details` itself) moves the concatenated reasoning text into `providerOptions.openaiCompatible[field]` — "Always set the field even when empty — some providers (e.g. DeepSeek) may return empty reasoning_content which still needs to be sent back" ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)). When the history was produced by a different `provider/model`, reasoning parts become plain text and their `providerMetadata` (signatures) is dropped ([message-v2.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/message-v2.ts)). Prompt caching (`applyCaching`) puts breakpoints on the first two system messages and the last two non-system messages, in the provider's own shape (`anthropic.cacheControl`, `openrouter.cacheControl`, `bedrock.cachePoint`, `openaiCompatible.cache_control`, `alibaba.cacheControl`), for Anthropic-ish and Alibaba models only ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)).

Two hard numbers define the failure envelope. **`OUTPUT_TOKEN_MAX = 32_000`** caps `maxOutputTokens = min(model.limit.output, 32_000)` unless `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` overrides it, and issue #18108 lists the consequences — Opus 128k output capped, large `write()` calls cut mid-JSON, truncation misread as invalid tool calls, doom-loop detection defeated — with no resolution PR ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts), [runtime-flags.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/effect/runtime-flags.ts), [#18108](https://github.com/anomalyco/opencode/issues/18108)). And `DOOM_LOOP_THRESHOLD = 3`: a `tool-call` event is compared against the last three parts *of the current assistant message only*; if all three are completed tool parts with the same name and `JSON.stringify`-equal input, a `doom_loop` permission is asked ([processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)). Because `slice` precedes `filter`, an interleaved text part or a new assistant message resets it, alternating A/B/A/B cycles are never caught, and the threshold is not configurable ([#25254](https://github.com/anomalyco/opencode/issues/25254), [#47759](https://github.com/anomalyco/opencode/issues/47759), [#23531](https://github.com/anomalyco/opencode/issues/23531)). rolo-claude's `loop_guards` already hashes `(tool, canonical sorted-key JSON)` cumulatively across the turn; the period-2 detector is the one missing piece.

The retry policy is worth copying whole. `retryable()` never retries `ContextOverflowError`, always retries HTTP ≥ 500 and 429 (and OpenAI 404, because "openai sometimes returns 404 for models that are actually available"), and otherwise matches the message or body against seven regex groups covering status codes, rate-limit phrasings, overload/unavailable/provider-error phrasings, connection failures (`terminated`, `fetch failed`, `ECONNREFUSED`, `ECONNRESET`, `ETIMEDOUT`), timeout phrasings, "try your request again"/"resource exhausted", and "try again later"/"temporarily at capacity"; `delay()` prefers `retry-after-ms`, then `retry-after` (seconds or HTTP date), else **`2000 × 2^(attempt−1)` with 25 % jitter, capped at 30 s when no header is present**, up to **five retries**, re-running the entire stream and publishing a `retry` status with the attempt and next time for the UI ([retry.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/retry.ts), [provider/error.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/error.ts), [processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)). A `rawFinishReason === "network_error"` from the SDK is converted into a retryable `ResponseStreamError` ([ai-sdk.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm/ai-sdk.ts)). Context overflow is classified separately by a list of ~27 regexes — `/prompt is too long/i`, `/request_too_large/i`, `/exceeds the context window/i`, `/maximum context length is \d+ tokens/i`, `/context[_ ]length[_ ]exceeded/i`, `/too many tokens/i`, `/token limit exceeded/i`, `/model_context_window_exceeded/i` among them — with exclusions for `/rate limit/i`, `/too many requests/i` and `/^(throttling error|service unavailable):/i`, plus HTTP 413 and `body.error.code === "context_length_exceeded"`; the file admits "z.ai: can accept overflow silently (needs token-count/context-window checks)" ([provider-error.ts](https://github.com/anomalyco/opencode/blob/dev/packages/llm/src/provider-error.ts), [provider/error.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/error.ts)). rolo-claude's `errors.py` has a 1-2-4-8-16 s ladder that *adds* `Retry-After` on top, a ten-pattern overflow regex, and a status-only retry decision; the OpenCode additions are the message-pattern retry classifier, jitter, `retry-after-ms`, the SSE chunk-idle watchdog and the extra overflow phrasings.

Context management uses provider-reported usage, not estimates, for the trigger. After every `step-finish`, `isOverflow` computes `count = tokens.total || input + output + cache.read + cache.write` and compares it with **`usable = (limit.input ? limit.input − reserved : context − maxOutputTokens)` where `reserved = compaction.reserved ?? min(20_000, maxOutputTokens)`**; overflow halts the stream (`Stream.takeUntil`), creates a compaction message and continues the loop, and a provider `ContextOverflowError` triggers the same path unless `compaction.auto === false` ([overflow.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/overflow.ts), [processor.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)). Compaction first prunes, if `compaction.prune` is on (docs default **false**): it walks messages backwards, skips the two most recent user turns, protects the newest **40 000** tokens of completed tool output and any `skill` output, and stamps older outputs `compacted` only if that frees more than **20 000** tokens; then it keeps a verbatim tail of whole recent turns within `preserve_recent_tokens ?? min(15_000, max(2_000, floor(usable × 0.25)))`, serialises the head as `[User]`/`[Assistant]`/`[Assistant reasoning]`/`[Assistant tool call] name({...})`/`[Tool result]` (truncated to 2 000 characters), and asks the `compaction` agent's model (else the session model) with `tools: {}` for a fixed Markdown summary — `## Objective`, `## Important Details`, `## Work State` (`### Completed`/`### Active`/`### Blocked`), `## Next Move`, `## Relevant Files` — under the rules "Keep every section, even when empty", "Preserve exact file paths, symbols, commands, error strings, URLs, and identifiers", "Do not mention the summary process"; a prior summary is carried forward with "The <prior-summary> is discarded after this … Where they conflict, the conversation wins" ([compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts), [core compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/compaction.ts)). Afterwards the last real user message is replayed (media replaced by `[Attached <mime>: <name>]`) if the trigger was an overflow error, otherwise a synthetic user message **"Continue if you have next steps, or stop and ask for clarification if you are unsure how to proceed."** is appended; if even the summary overflows the session stops with "Conversation history too large to compact" ([compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)). Token estimation elsewhere is `chars / 4` ([token.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/util/token.ts)). Cost is computed locally from models.dev prices with **reasoning billed at the output rate** and OpenRouter's authoritative `usage.cost` ignored, and there is still no `/cost` or `/usage` command (open feature request) ([session.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/session.ts), [#41915](https://github.com/anomalyco/opencode/issues/41915)). Model fallback on transient errors is not implemented (PR #49125 proposes a per-model `fallback: []` list after the retry policy is exhausted) ([PR #49125](https://github.com/anomalyco/opencode/pull/49125)).

### Corrections to the two earlier reports

Five statements in the earlier reports need adjusting against the code. First, the "Per-family sampling and budget defaults" table attributes a Qwen3-Coder temperature of **0.55 to OpenCode; `transform.ts` contains no Qwen rule** — `temperature()` returns `undefined` for Qwen ids, and the only Qwen-specific behaviour is that `qwen` ids get no reasoning variants and `alibaba-cn` reasoning models get `enable_thinking: true` ([transform.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)); the vendor presets in the adapter-rules table (0.7 / 0.8 / top_k 20 / repetition_penalty 1.05 for Coder-480B, 1.0 / 0.95 / 40 for Coder-Next) stand unchanged. Second, the earlier claim that OpenCode "demands headed sections with one corrective retry" is not in `dev`: the summariser validates only that the text is non-empty, so H5's corrective retry is rolo-claude's own design (keep it). Third, "triggers compaction at min(input_limit − 20,000, context − max(output_reserve, 20,000))" is a blend of two code paths — v1 `overflow.ts` uses `limit.input − reserved` *or* `context − maxOutputTokens`, and the v2 core package uses `context − max(output, 20_000)` with `DEFAULT_KEEP_TOKENS = 8_000` — and "keeps 15,000 recent tokens" is really `min(15k, max(2k, 25 % of usable))` ([overflow.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/overflow.ts), [core compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/compaction.ts), [compaction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts)). Fourth, "OpenCode-style stubbing of old tool bodies outside a 40k protection window" needs three qualifiers: pruning is **off by default**, runs only when it frees > 20 000 tokens, and protects `skill` outputs. Fifth, the "364 identical grep calls … no repeated-action detection" line should read "a doom-loop guard exists but inspects only the current assistant message and is auto-approved under `--auto`", which is the more useful lesson. The earlier reports' Databricks OpenCode recipe (`@ai-sdk/openai` provider at `<ws>/ai-gateway/mlflow/v1`, model `databricks-oss/system.ai.glm-5-2`) is confirmed by the `ucode` source, which additionally registers `databricks-anthropic` (`@ai-sdk/anthropic` at `/ai-gateway/anthropic/v1`, `toolStreaming: false` per model) and `databricks-google` (`@ai-sdk/google` at `/ai-gateway/gemini/v1beta`), and notes that per-model `headers` are the only way to beat OpenCode's injected `User-Agent` ([opencode.py](https://github.com/databricks/ucode/blob/main/src/ucode/agents/opencode.py), [databricks.py](https://github.com/databricks/ucode/blob/main/src/ucode/databricks.py), [Databricks OpenCode page](https://docs.databricks.com/aws/en/ai-gateway/coding-agent-opencode)). Kimi sampling in OpenCode (0.6 / 1.0, gated by models.dev's `temperature` flag, so nothing is sent for `kimi-k3`) is consistent with the adapter-rules resolution "omit on Moonshot first-party endpoints".

## TUI, sessions, config and Linux: leader keys, git-backed undo, SQLite regrets

The TUI is a SolidJS app on OpenTUI inside the Bun binary, talking to its own server over the SDK and `EventSource`; its signature is a **leader-key keymap (`ctrl+x`, `leader_timeout` 2000 ms) with roughly 150 remappable actions in `tui.json`**, a `ctrl+p` command palette, which-key overlay (`ctrl+alt+k`), `@file` fuzzy mentions with `#L10-20` ranges and configured `@alias` references, a `!` prefix that runs a shell command whose output "is added to the conversation as a tool result", Emacs-style input editing, `tab`/`shift+tab` cycling primary agents, `ctrl+t` cycling reasoning variants, `f2` cycling recent models, `<leader>u`/`<leader>r` for git-backed message undo/redo, `<leader>c` compact, `<leader>l` sessions, `<leader>y` copy, and parent/child session navigation (`<leader>down`, `left`/`right`, `up`) instead of tabs ([keybinds docs](https://opencode.ai/docs/keybinds/), [TUI docs](https://opencode.ai/docs/tui/)). `tui.json` also holds `diff_style: auto|stacked`, cursor style, `mouse` (default on), scroll speed/acceleration, and an `attention` block for desktop notifications and sounds that fire only when the terminal is blurred ([TUI docs](https://opencode.ai/docs/tui/)). Themes are JSON files with `defs`, hex/ANSI/`{dark,light}` values and 60+ properties; the built-in **`system` theme derives greys from the terminal background and uses ANSI 0–15 for syntax**, which is the lowest-effort way to look native in kitty/xterm/tmux ([themes docs](https://opencode.ai/docs/themes/)). Permission prompts are inline cards with `once`/`always`/`reject` and a `ctrl+f` fullscreen expansion; `/thinking` only toggles display ([permissions docs](https://opencode.ai/docs/permissions/), [keybinds docs](https://opencode.ai/docs/keybinds/), [TUI docs](https://opencode.ai/docs/tui/)). On Linux the record is mixed: tmux rendering broke in 1.2.21–1.2.24 (fixed 1.2.25), kitty-keyboard-protocol handling corrupts input on some terminals with no opt-out, tmux prefix keys leak after mouse selection, and copy/paste needs `xclip`/`xsel` or `wl-clipboard` ([#16351](https://github.com/anomalyco/opencode/issues/16351), [#16967](https://github.com/anomalyco/opencode/issues/16967), [#51086](https://github.com/anomalyco/opencode/issues/51086), [#12529](https://github.com/anomalyco/opencode/issues/12529), [troubleshooting](https://opencode.ai/docs/troubleshooting/)).

Undo is message-granular and git-backed: `revert` records a snapshot from an isolated git repo at `Global.Path.data/snapshot/[projectID]/[hash]` (`track()`/`restore()`/`revert(patches)`), flags the reverted messages until the next prompt's `cleanup` deletes them, and `unrevert` restores the pre-revert snapshot; the SDK exposes `session.revert/unrevert`, and the `snapshot` config key turns it off ([revert.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/revert.ts), [DeepWiki storage](https://deepwiki.com/sst/opencode/2.9-storage-and-database), [config docs](https://opencode.ai/docs/config/)). Sessions moved to **SQLite (`~/.local/share/opencode/opencode.db`, Drizzle) in v1.2.0**, with `session`/`message`/`part` tables holding JSON `data` columns and, in 2026, event-sourced `session_v2`/`session_message` tables layered over the frozen v1 ones; the migration "assumed DB exists = sessions already migrated" and permanently orphaned sessions for incremental upgraders, Windows path normalisation changed project hashes, and non-git sessions lost their leading `/` ([sql.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/sql.ts), [dax on X](https://x.com/thdxr/status/2022562561732812841), [#13654](https://github.com/anomalyco/opencode/issues/13654), [#13636](https://github.com/anomalyco/opencode/issues/13636), [#36178](https://github.com/anomalyco/opencode/issues/36178), [#50521](https://github.com/anomalyco/opencode/issues/50521)). Earlier JSON storage had its own disk-full and corrupted-file crashes ([#7607](https://github.com/anomalyco/opencode/issues/7607), [#10904](https://github.com/anomalyco/opencode/issues/10904)). Sessions can be continued (`-c`), resumed (`-s`), forked (`--fork`, `POST /session/:id/fork`), shared to public `opncd.ai/s/<id>` links (`share: manual|auto|disabled`), exported with `opencode export --sanitize`, imported from a file or share URL, and summarised with `opencode stats --days --tools --models`; titles come from `small_model` ([CLI docs](https://opencode.ai/docs/cli/), [share docs](https://opencode.ai/docs/share/), [config docs](https://opencode.ai/docs/config/)).

Configuration is `opencode.json(c)` merged lowest-to-highest from a remote `.well-known/opencode`, `~/.config/opencode/opencode.json`, `OPENCODE_CONFIG`, the project file (walking up), `.opencode/` directories, `OPENCODE_CONFIG_CONTENT`, then managed `/etc/opencode/` and macOS MDM, with `{env:VAR}`/`{file:path}` substitution and a published JSON schema; agents, commands, skills, plugins, tools and themes are Markdown/JS/JSON files in `{agent,agents}`, `{command,commands}`, `{skill,skills}`, `{plugin,plugins}`, `{tool,tools}`, `themes` subfolders ([config docs](https://opencode.ai/docs/config/), [config.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/config/config.ts)). Its Claude Code compatibility surface is narrow and explicit: rules read `AGENTS.md` first, then **`CLAUDE.md` walking up to the git root and `~/.claude/CLAUDE.md`**, gated by `OPENCODE_DISABLE_CLAUDE_CODE(_PROMPT|_SKILLS)`; skills read `.claude/skills/*/SKILL.md` and `~/.claude/skills/*/SKILL.md` (plus `.agents/skills`); **nothing reads `.claude/agents`, `.claude/commands`, `.mcp.json` or `~/.claude.json`** ([rules docs](https://opencode.ai/docs/rules/), [instruction.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/instruction.ts), [skill/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/skill/index.ts), [agent.ts loader](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/config/agent.ts), [command.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/config/command.ts), [mcp/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/mcp/index.ts)). Claude Pro/Max OAuth was removed in v1.3.0 by PR #18186 ("anthropic legal requests", merged 2026-03-19) after Anthropic's January 2026 server-side block; the providers page now says "Anthropic explicitly prohibits this", so Claude reaches OpenCode only by API key or gateway — the same stance rolo-claude already takes ([PR #18186](https://github.com/anomalyco/opencode/pull/18186), [providers docs](https://opencode.ai/docs/providers/)). Plugins are JS modules with ~21 typed hooks (`chat.message`, `chat.params`, `chat.headers`, `permission.ask`, `tool.execute.before/after`, `shell.env`, `experimental.session.compacting`, `experimental.chat.system.transform`, …) plus an event stream; MCP config is `mcp.<name>: {type: local|remote, command|url, environment|headers, oauth, timeout}` with tools named `servername_toolname`, Streamable HTTP falling back to SSE, `structuredContent` serialised to JSON text when `content` is absent, and a 30 000 ms connect timeout in code where the docs say 5 000 ([plugin index.ts](https://raw.githubusercontent.com/anomalyco/opencode/dev/packages/plugin/src/index.ts), [MCP docs](https://opencode.ai/docs/mcp-servers/), [mcp/index.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/mcp/index.ts), [mcp/catalog.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/mcp/catalog.ts)). LSP (30+ servers, auto-download) and formatters (~20) are bundled but off by default, and the docs themselves warn LSP servers "can get out of sync, use significant memory … and slow down agent workflows" ([LSP docs](https://opencode.ai/docs/lsp/), [formatters docs](https://opencode.ai/docs/formatters/)). On Kali the install is `curl -fsSL https://opencode.ai/install | bash` (57.8 MB x64 tarball, 60.1 MB musl), state is split XDG-style across `~/.config/opencode`, `~/.local/share/opencode` (`auth.json`, `opencode.db`, `log/`, `mcp-auth.json`) and `~/.cache/opencode` (auto-downloaded `bin/rg`, plugin `node_modules`), and the recurring Linux failures are the ripgrep download behind proxies/offline and clipboard tooling ([releases/latest](https://api.github.com/repos/anomalyco/opencode/releases/latest), [troubleshooting](https://opencode.ai/docs/troubleshooting/), [#51022](https://github.com/anomalyco/opencode/issues/51022), [#21646](https://github.com/anomalyco/opencode/issues/21646)).

## What rolo-claude should adopt, adapt and avoid

The filter is rolo-claude's own constraints. It reuses Claude Code's files, so any OpenCode idea that lives in `opencode.json`/`tui.json` must be re-expressed in `settings.json`, `~/.claude/keybindings.json`, `.claude/agents`, `.claude/commands` and `.mcp.json`. It has no safety heuristics and auto mode never prompts, so OpenCode's `ask`-defaults, `external_directory` prompts and tree-sitter command classification are irrelevant *as gates* but still relevant *as rule-evaluation fidelity* for the user's own `Bash(git *)` rules, and its loop breaker must stay armed where OpenCode's is auto-approved. It supports steering, which OpenCode lacks. It targets Kali first, so OpenCode's tmux/kitty regressions are a test list, not a design. And, per the earlier reports, it already has a log-derived request, a repair layer, a per-turn loop breaker, an overflow parser and a model table — so most OpenCode mechanics are refinements of existing modules rather than new subsystems. ## Conclusion

OpenCode's value to rolo-claude is inversely proportional to how visible the feature is. Its surfaces — OpenTUI, the Hono server, SQLite, share links, ACP, the JS plugin bus — are the parts that cost the project its migration incidents and its tmux regressions, and none of them fit a Python/Textual harness that mirrors Claude Code's files. Its invisible parts — a replacer chain with published thresholds, an error-as-tool-result discipline, a retry classifier that reads error bodies, an overflow gate driven by provider usage, prune constants and a compaction template, a per-model transform table gated by a catalog's `temperature` flag, and `interleaved.field` replay with an empty string for DeepSeek — are exactly the kind of code that made 210k-star adoption survive DeepSeek, Kimi and GLM on third-party hosts, and every one of them is a few hundred lines of dependency-free Python that slots into modules rolo-claude already has.

The deeper implication is that the two open-weight harness lineages have converged on the same eight branches the adapter-rules report named, and OpenCode's issue tracker is the best public regression suite for them: its "closed, not planned" DeepSeek and Kimi issues are the test cases rolo-claude's `reasoning_echo` and `args_repair` must pass, and its one spectacular loop is the reason the breaker stays on in auto mode. Once H5 lands items 1–8, rolo-claude will be strictly ahead of OpenCode on the loop (steering, length handling, empty-completion retry, cumulative loop guard, full-fidelity stream-json) while borrowing its best tool and provider mechanics; what it will still lack — git-backed undo, remappable chords, a palette — is a U5 problem, not an architecture problem.

### B. Retry classifier and backoff ([`session/retry.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/retry.ts), [`provider/error.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/error.ts), [`ai-sdk.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/llm/ai-sdk.ts))

```python
RETRY_INITIAL_DELAY_MS = 2000
RETRY_BACKOFF_FACTOR = 2
RETRY_JITTER_FACTOR = 0.25
RETRY_MAX_DELAY_NO_HEADERS_MS = 30_000
RETRY_MAX_DELAY_MS = 2_147_483_647          # only reachable via a Retry-After header
RETRY_MAX_RETRIES = 5

RETRYABLE_MESSAGE_PATTERNS = [               # all case-insensitive; groups 3 and 4 had elisions in the note
    r"429|500|502|503|504|524",
    r"rate increased too quickly|rate limit|rate-limit|rate_limit|too many requests",
    r"overloaded|service unavailable|internal error|provider returned error|provider_returned_error",
    r"terminated|fetch failed|socket hang up|connection refused|econnrefused|econnreset|etimedout",
    r"^timeout$|\b(?:request|response|connection|network|stream|read) (?:timeout|timed out|time out)\b",
    r"try your request again|retry your request|resource exhausted|resource_exhausted",
    r"\btry again (?:later|in\b)|\b(?:currently|temporarily) at capacity\b",
]

def retryable(err) -> bool:
    if err.category == "CONTEXT_WINDOW_EXCEEDED":      # ContextOverflowError is never retried
        return False
    if err.status is not None and (err.status >= 500 or err.status == 429):
        return True
    if err.status == 404 and err.host == "openai":     # "openai sometimes returns 404 for models that are actually available"
        return True
    if err.raw_finish_reason == "network_error":       # ai-sdk.ts converts this to a retryable stream error
        return True
    if err.kind in ("header_timeout", "sse_read_timeout"):   # HeaderTimeoutError / ResponseStreamError are isRetryable
        return True
    text = f"{err.message} {err.body_text}"
    return any(re.search(p, text, re.I) for p in RETRYABLE_MESSAGE_PATTERNS)

def delay_ms(attempt: int, headers: dict) -> int:      # attempt is 1-based
    if "retry-after-ms" in headers:
        return min(int(headers["retry-after-ms"]), RETRY_MAX_DELAY_MS)
    if "retry-after" in headers:                       # seconds, or an HTTP date
        v = headers["retry-after"]
        secs = float(v) if v.strip().isdigit() else max(0.0, (parsedate_to_datetime(v) - now()).total_seconds())
        return min(int(secs * 1000), RETRY_MAX_DELAY_MS)
    base = RETRY_INITIAL_DELAY_MS * (RETRY_BACKOFF_FACTOR ** (attempt - 1))
    return min(int(base + base * RETRY_JITTER_FACTOR * random.random()), RETRY_MAX_DELAY_NO_HEADERS_MS)
```

The whole stream is re-run on retry (the SDK's own `maxRetries` is 0; title generation alone passes `retries: 2`), and a `retry` status event `{attempt, message, next}` is published for the UI. Transport timeouts: `headerTimeout` 300 000 ms, `chunkTimeout` 300 000 ms between SSE chunks ("SSE read timed out"), optional total `timeout` ([provider.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/provider.ts)). Databricks' 429 body (`limit_type`, `retry_after`) and its pre-admission rule from the earlier reports slot into `delay_ms` as a `retry-after` source.

### C. Edit replacer chain ([`tool/edit.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/edit.ts))

Parameters: `filePath`, `oldString`, `newString` (must differ), `replaceAll` (optional). Pre-checks, verbatim errors: identical strings → `No changes to apply: oldString and newString are identical.`; empty `oldString` on an existing file → `oldString cannot be empty when editing an existing file...`; missing file → `File ${filePath} not found`; directory → `Path is a directory...`. Try each replacer in order; the first that yields exactly one match wins (or all matches when `replaceAll`); more than one match without `replaceAll` → `Found multiple matches for oldString. Provide more surrounding context...`; none → `Could not find oldString in the file. It must match exactly...`.

| Order | Replacer | Matching rule | Threshold |
|---|---|---|---|
| 1 | Simple | exact substring | — |
| 2 | LineTrimmed | sliding window of `len(oldLines)` lines; each line compared after `trim()` | equality |
| 3 | BlockAnchor | first and last lines of `oldString` (trimmed) must match the candidate's first and last lines; middle lines scored by Levenshtein similarity; single best candidate | similarity ≥ **0.65** |
| 4 | WhitespaceNormalized | runs of whitespace collapsed to one space on both sides before comparing *(reconstructed)* | equality |
| 5 | IndentationFlexible | common leading indentation stripped from `oldString` and from each candidate window before comparing | equality |
| 6 | EscapeNormalized | `\n`, `\t` and similar escape sequences in `oldString` unescaped, then compared *(partly reconstructed)* | equality |
| 7 | TrimmedBoundary | leading/trailing whitespace of the whole `oldString` trimmed before comparing *(reconstructed)* | equality |
| 8 | ContextAware | first/last lines as anchors; fraction of middle lines that match (trimmed) | ≥ **50 %** of middle lines |
| 9 | MultiOccurrence | every exact occurrence | used for `replaceAll` |

Span guard applied to any fuzzy hit: reject with `Refusing replacement because the matched span is much larger than oldString...` when the matched span has ≥ `max(oldLines + 3, oldLines * 2)` lines or its trimmed length is > `max(len(oldString) + 500, len(oldString) * 4)`. After a successful edit: preserve `\n` vs `\r\n`, emit a unified diff, append LSP diagnostics as `LSP errors detected in this file, please fix:` when available. Tool prompt rules ([edit.txt](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/edit.txt)): the file must have been read first; "preserve the exact indentation (tabs/spaces) as it appears AFTER the line number prefix"; never include the `[number]: ` prefix; prefer `replaceAll` for renames. rolo-claude's existing per-line-strip stage is stage 2 plus its own re-indentation; keep that re-indentation for stages 2, 4, 5 and 7.

### D. Compaction: overflow gate, prune, tail, summary template ([`overflow.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/overflow.ts), [`compaction.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/compaction.ts), [`core compaction.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/compaction.ts), [`transform.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts), [`message-v2.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/message-v2.ts))

```python
OUTPUT_TOKEN_MAX = 32_000          # OpenCode's hard cap -- rolo-claude uses its per-host max_tokens_budget instead
COMPACTION_BUFFER = 20_000
PRUNE_MINIMUM = 20_000             # prune only if at least this many tokens would be freed
PRUNE_PROTECT = 40_000             # newest completed tool-output tokens never pruned
PRUNE_PROTECTED_TOOLS = ["skill"]
TOOL_OUTPUT_MAX_CHARS = 2_000      # per tool result in the summariser's head serialisation
MIN_PRESERVE_RECENT_TOKENS = 2_000
MAX_PRESERVE_RECENT_TOKENS = 15_000
CHARS_PER_TOKEN = 4                # estimate = round(len(text) / 4), used only where no usage exists

def max_output_tokens(model, cap=OUTPUT_TOKEN_MAX): return min(model.limit.output, cap) or cap
def usable(model, cfg):
    if model.limit.context == 0: return 0
    reserved = cfg.compaction.reserved if cfg.compaction.reserved is not None else min(COMPACTION_BUFFER, max_output_tokens(model))
    return max(0, model.limit.input - reserved) if model.limit.input else max(0, model.limit.context - max_output_tokens(model))
def is_overflow(tokens, model, cfg):
    if cfg.compaction.auto is False or model.limit.context == 0: return False
    count = tokens.total or (tokens.input + tokens.output + tokens.cache_read + tokens.cache_write)
    return count >= usable(model, cfg)          # evaluated after EVERY step-finish from provider-reported usage
def preserve_recent_budget(model, cfg):
    return cfg.compaction.preserve_recent_tokens or min(MAX_PRESERVE_RECENT_TOKENS, max(MIN_PRESERVE_RECENT_TOKENS, usable(model, cfg) * 25 // 100))
```

Prune walks messages newest → oldest, skips the two most recent user turns, stops at a prior summary or an already-compacted part, and stamps `part.state.time.compacted`; replay renders those as `[Old tool result content cleared]` with attachments removed, renders tool parts still `pending`/`running` as an error result `[Tool execution was interrupted]`, and skips assistant messages left with no parts. Tail selection keeps whole recent user turns while they fit (optionally capped by `tail_turns`) and may split the boundary turn. The head is serialised as `[User]: …`, `[Assistant]: …`, `[Assistant reasoning]: …`, `[Assistant tool call]: name({...})`, `[Tool result]: <first 2000 chars>\n[truncated]`, sent with `tools: {}` and `system: []`; a tool call during the summary throws `Tool call not allowed while generating summary`. Summary instruction (verbatim core text): "Create a new anchored summary from the conversation history in the <conversation> tags above so another coding agent can continue the work." Required Markdown sections, in order:

```
## Objective
## Important Details
## Work State
### Completed
### Active
### Blocked
## Next Move
## Relevant Files
```

Rules: "Keep every section, even when empty. Use terse bullets, not prose paragraphs. Preserve exact file paths, symbols, commands, error strings, URLs, and identifiers when known." "Do not mention the summary process or that context was compacted." With a prior summary: "Carry forward objectives, constraints, user directives, decisions, and parallel workstreams from the <prior-summary> even when the <conversation> does not mention them." and "The <prior-summary> is discarded after this: anything you do not carry into the new summary is lost … Where they conflict, the conversation wins". After compaction: if the trigger was an overflow *error*, replay the last real user message with media parts replaced by `[Attached <mime>: <name>]`; otherwise append the synthetic user message `Continue if you have next steps, or stop and ask for clarification if you are unsure how to proceed.` (metadata `compaction_continue: true`). If the summary request itself overflows: `ContextOverflowError("Conversation history too large to compact - exceeds model context limit")`. Config: `compaction: {auto: true, prune: false, reserved, tail_turns, preserve_recent_tokens}`, env `OPENCODE_DISABLE_AUTOCOMPACT`, `OPENCODE_DISABLE_PRUNE`. Cache placement: system collapsed to ≤ 2 messages; tools name-sorted; `cache_control: {type: "ephemeral"}` on the first two system messages and the last two non-system messages (message-level for anthropic/bedrock, else on the last content part). For rolo-claude, H5's dsh-style 80 % trigger and prefix replay remain the mechanism; OpenCode's `usable` is the floor that the 80 % rule must never exceed, and its prune constants and replay strings apply as written.

### E. Doom-loop rule ([`session/processor.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/processor.ts)) and the rolo-claude upgrade

Request fields OpenCode emits only when the host is OpenRouter: headers `HTTP-Referer: https://opencode.ai/`, `X-Title: opencode` (attribution; rolo-claude may send its own or none); body `usage: {include: true}` (OpenRouter now always includes usage, so harmless); `reasoning: {effort: "<low|medium|high|xhigh>"}` for variants and `reasoning: {enabled: false}` for small-model calls on Google models; `provider: {order, allow_fallbacks, only, ignore, sort, data_collection, require_parameters}`; `cacheControl: {type: "ephemeral"}` for Anthropic models; `reasoning_details` replayed via `providerMetadata.openrouter.reasoning_details` by the SDK — in Python, replay the array byte-for-byte on the assistant message (the adapter-rules report's rule). Keep every one of these fields out of Databricks requests (400 on unknown fields).
