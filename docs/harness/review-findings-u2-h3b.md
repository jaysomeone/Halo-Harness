## Findings

1. **critical** — `halo_harness/agent/loop.py:975-990` (+`948-973`, `1079-1089`) — `_await_reply` pops the waiter slot before blocking, so the UI thread's `resolve_permission`/`resolve_question` find nothing and every PermissionCard/QuestionCard answer is silently dropped (their False return is ignored). — Verified in `default` mode: Write asks, `session._permission_waiters` is already empty when the card renders, and pressing "1" clears the card and re-enables the input while no tool_result/turn_done arrives until Esc/quit aborts the wait, after which the approved Write reports "Permission request dismissed or interrupted". — Keep the slot registered while waiting (`get`, then pop in a `finally`) and toast when `answer_*` returns False.
2. **major** — `halo_harness/agent/loop.py:518-523,1068-1130,1174` + `halo_harness/controller.py:136-144` — `abort` is never checked between tool calls, `_step` discards the partial reply on abort without logging it or an interrupt marker, and `_pump_turn` clears `abort` for every queued `user_input`, including prompts queued ahead of quit's `None` sentinel. — Verified: Esc during `sleep 8` in a `[Bash sleep 8, Write]` message killed the Bash but still ran the Write (file created), and `quit()` with one prompt typed while busy started a new model call plus a new `sleep 8`, returning only after the full 5 s join (then `close_all` adds up to 5 s) with the worker alive and the child orphaned at exit. — Check `abort` before each dispatch and synthesize "interrupted" results for the rest, log the partial text plus a `[Request interrupted by user]` node (H4 steering needs the same), and have quit set a stopping flag that `run()` checks before any queued command.
3. **major** — `halo_harness/permissions.py:1304,1375-1376,1495` + `agent/loop.py:895-896` + `tui/app.py:282-290` — Interactive `ask` decisions never carry a `suggested_rule` (only the print-mode branches call `suggest_rule`), and when one exists the TUI keeps only `split(", ")[0]` of the comma-joined per-segment suggestions, so the rule shown and the rule written differ. — Verified: a default-mode Write's `permission_request` has `suggested_rule: None`, so "2 Yes, session" and "3 Yes, always" learn nothing, write nothing to `.claude/settings.local.json`, show no toast, and the next identical Write prompts again; a `make build && npm test` card would show two rules and write one. — Compute `suggest_rule` for every interactive ask and pass a list, write and learn exactly what the card displays in 2.1.281's `Bash(npm test *)` form (binary §5), and name the destination file on the card.

5. **major** — `halo_harness/tui/dispatch.py:32-38,105-156` + `tui/widgets/diffview.py:20` + `tui/app.py:127-133,285-290` + `tui/launch.py:39` — Nothing isolates exceptions in `_drain`/`apply_event`/card callbacks although handlers raise on reachable input (the loop emits `tool_use_ready` with the RAW input when repair rejects it and `DiffView` calls `.splitlines()` on it; the rule write catches only `SettingsWriteRefused`, so OSErrors escape once finding 3 is fixed; `_git_branch` catches OSError but not `TimeoutExpired`), and `run_tui` has no `finally: controller.quit()`. — Verified: an Edit with `old_string: null` (repair: "must be string, got NoneType") kills the TUI with AttributeError, and a `question` event with Claude Code-style `{label, description}` options dies with VisualError, each time leaving a running Bash child (its own session on Linux) orphaned. — Wrap each `apply_event` in try/except that renders an error note, coerce card and diff inputs to str, catch OSError/`SubprocessError` (and move git off the UI thread), and call `controller.quit()` in a `finally` in `run_tui`.
6. **major** — `halo_harness/agent/loop.py:1198-1212` + `tui/app.py:294-297` — `Session.run()` reads commands only between turns (the worker is parked inside the turn generator), so Shift+Tab's `set_mode` lands only after the whole turn while the status bar shows the new mode at once; prompts typed while busy queue as whole new turns, and H4's `steer` would be stuck in the same queue. — Flipping `default` to `auto` mid-turn still produces a permission card for every remaining tool call of that turn (in `plan`, a deny), breaking "Auto mode = uninterrupted"; `CLAUDE_CHROME_PERMISSION_MODE` is likewise frozen at spawn. — Set `permission_engine.mode` directly from the UI thread (an atomic attribute write, like `abort.set()`), emit the status event from the controller, and give H4 a thread-safe side channel checked per chunk and per tool.
