# H11 review findings (commit 4305c33 "H11: Claude models through the user's Claude subscription")

Format: severity — file:line — defect — failure scenario — fix. Line numbers refer to a `git archive 4305c33` snapshot; the diff under review is `git diff v0.3.1..HEAD -- . ':!docs' ':!reports'`. "Verified" means reproduced with scratch scripts against that snapshot: a real `Session` on `tests/helpers/fake_claude_cc.py` (or a small variant of it that replays a shape the real binary was observed to emit), or the real CLI in a subprocess. Hosts: Windows 11 / Python 3.11.7, and WSL Ubuntu 24.04 / Python 3.12.3 (`~/halo-harness-wt-venv`, mcp 2.2.0, LF export). the owner's home was always redirected to a scratch dir. "Verified live" means the real `claude` 2.1.284 on this box: the npm shim `claude.CMD` → cmd.exe → native `claude.exe`, logged in via claude.ai. Those probes used haiku and `--no-session-persistence`, except three one-turn "pong" runs that left transcripts under scratch-cwd project slugs. `claude login`/`logout` were never run, and `~/.claude/.credentials.json` was never read. Binding constraints (no safety/refusal logic, auto = everything except the user's own deny/ask rules and hooks, `bypassPermissions` on the claude subprocess) are not reported. The only repo file touched is this one.

## Findings

1. **critical** — `agent/cc_runtime.py:393-413,429-430,469-475` — Every stdin line (the turn and each steer) is counted as one expected `result`, and the turn ends only when the count reaches 0. claude does not answer line by line. — Verified live (haiku, stream-json): (a) one steer sent between the tool calls of a 5-call turn was absorbed into that turn, giving 1 `result` for 2 lines ("FINISHED PINEAPPLE", `num_turns` 6); (b) two lines queued behind a running turn got one follow-up turn that answered both, giving 3 lines and 2 results (`queued_turn_count` 0 on both). With a fake that replays (a), on Windows and WSL, one `session.steer()` left `pending`=1: no `DONE`, and `turn()` was still running after 15 s. The TUI stays busy and `-p --input-format stream-json` never finishes; only Esc ends the turn, and Esc kills claude. The steer is also logged when it is sent, ahead of output it did not influence. Every `result` emits `status idle` while a queued follow-up is still running.
