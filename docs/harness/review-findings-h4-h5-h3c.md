## Findings

1. **critical** — `rolo_claude/agent/compact.py:65-98` (+`agent/loop.py:977-992,1225`, `model.py:106-108`) — The auto-compaction gate subtracts models.json's advertised `max_output_tokens` (OpenRouter's max_completion, often close to the whole window) instead of the output actually requested, ports OpenCode's `usable` without its 32 000 output cap, and nothing prevents back-to-back compactions. — Verified: of the 105 DeepSeek/Kimi/GLM/Qwen/MiniMax entries in rolo's models.json, 29 get a trigger of 0 (kimi-k2.5/k2.6/k2.7-code, qwen3-coder-next, qwen3.5-397b, minimax-m2) and 21 more a trigger under 40k (glm-5 at 9 011, deepseek-v3.2 at 26 214); a two-step Read turn on the Kimi K2.6 profile (262 144/235 929) made 2 summariser calls and wrote 2 `compacted` nodes, so every model call is followed by a full-context summarisation that replaces the history with a summary plus a 2 000-token tail, and `CLAUDE_CODE_AUTO_COMPACT_WINDOW` can't help because it goes through the same subtraction. — Reserve `min(requested max_tokens, 32 000)` as OpenCode does, floor the trigger at a sane share of the window (the plan's ≈70 % on 128k-class models), and skip auto-compaction when the post-compaction estimate is already at or above the trigger or the previous step compacted.
2. **critical** — `rolo_claude/tools/edit.py:291-316` — `find_replacement` takes `candidates[0]` from every multi-match fuzzy stage (LineTrimmed, WhitespaceNormalized, IndentationFlexible, EscapeNormalized, TrimmedBoundary, ContextAware), while OpenCode skips any candidate that isn't unique and ends with "Found multiple matches…". — Verified: in a file with two identical `x = 1` / `return x` blocks, an `old_string` indented by 2 instead of 4 spaces edits the first block and reports success "(matched via LineTrimmed)"; the TrimmedBoundary needle `"\nfoo\n"` edits the first `foo` anywhere in the file. These are silent wrong-location edits in user code, hitting exactly the weak, whitespace-drifting models the chain exists for. — Accept a stage only when it yields exactly one candidate (or all of them with `replace_all`), move past ambiguous stages, return the multiple-matches error if any stage was ambiguous and none was unique, and add adversarial near-duplicate tests.
3. **major** — `rolo_claude/agent/loop.py:1867-1874` (+`1343-1350`) — A steer noticed after a solo call breaks out of `_dispatch_tools` without writing results for the remaining `tool_use` blocks, and `_apply_pending_steers_events` appends the steer right after, breaking invariant rule 2 (every tool_use has a result). — Verified: `[Write a, Write b]` with a steer during `a` means `b` never runs and has no `tool_result` node, and the next request sends `("call_2", "(no result)")` (translate's placeholder), telling the model the write happened with empty output. On `ant:`/Databricks Claude the next request 400s, and so does every later turn in the process, because `find_unpaired_tool_use_ids` only checks the last assistant node. — Before applying a steer, synthesize an `is_error` result ("not run: the user sent a new message first") for every call that didn't run, and check pairing across all assistant nodes.
4. **major** — `rolo_claude/agent/loop.py:1016-1074,1209-1213` + `commands/builtins.py:112-115` — Compaction never fails safely. `agent/prune.py` is wired only into `/context`, so the "pruned ~N tokens" it reports never happens. The overflow path replays the exact prefix that just overflowed, and the summariser has no retry ladder and no abort check. Any failure (overflow, 429/5xx, auth, Esc) still writes the `compacted` marker with "(summary unavailable)". — Verified: an overflow on the main call led to two summariser calls that both overflowed, then the marker was written with "(summary unavailable)", hiding everything outside the ≤15k-token tail; a single 429 during auto-compaction, or Esc while it runs, does the same to a healthy session. — Prune (head/tail cuts plus stubs for old results) in `_derive_and_build` and before summarising. When the exact prefix overflows, serialise the head OpenCode-style (tool outputs ≤2 000 chars, no tools). Reuse `_step`'s retry ladder, and on failure return without writing the marker (report an error on overflow, carry on for auto).
5. **major** — `rolo_claude/controller.py:161-171` + `agent/loop.py:1967-2005,684-695,1106-1168` — `submit` ignores what `steer()` returns, `turn()` never drains the queue, and `steer_queued` fires only when a steer is applied. A steer that lands after the turn's last checkpoint (during Stop hooks, the final status/turn_done yields, or an error or Esc unwind) is accepted but not applied, and if the session goes idle between `busy` and `steer()` the text is dropped. — Verified: a steer accepted after turn 1's final `status` event was not applied. Turn 2's first model call was then cut at its first chunk, which logged an empty `[]` assistant node (a 400 on Anthropic routes); the stale steer landed after the new prompt and a third request was made. The TUI showed nothing when it was typed. — Make the busy check and enqueue atomic under `_steer_lock`, and have `turn()` drain leftovers under the same lock on exit and resubmit them as the next `user_input`. Emit `steer_queued` at enqueue time, and never log an empty assistant node for a cut.
6. **major** — `rolo_claude/hooks.py:216-245` + `agent/loop.py:488-492` — `CLAUDE_ENV_FILE` is parsed into literal `NAME=value` pairs (no `$VAR` expansion, no `source`) and merged over the Bash tool env, whereas 2.1.281 sources the file as a shell script before each Bash command ("Session environment script ready" in the binary). — The Claude Code docs' own SessionStart example `export PATH="$PATH:./node_modules/.bin"` sets PATH to that literal string. On Ubuntu/WSL (whose `/etc/profile` keeps the inherited PATH) system commands stop resolving in every Bash call; on Kali/Debian, `/etc/profile` resets PATH under `bash -lc`, so the addition silently vanishes; `export NODE_OPTIONS="$NODE_OPTIONS …"` breaks node. — Source the file in the Bash tool's shell before each command, as Claude Code does (or at least expand `$VAR`/`${VAR}` against the current env), and re-read it after compact/clear SessionStart hooks.
7. **major** — `rolo_claude/headless.py:325-342` + `agent/loop.py:420-421` — `SessionCatalog(names=frozen_registry.names())` is snapshotted before `frozen_registry.add_tool(ws_tool)`, and the Session logs `definitions_for(catalog.names)`. — Verified: with the `mcp` package installed and zero servers, WebSearch is in the registry but missing from the logged tool catalog sent to the model, so on OpenRouter the model is never offered H4's WebSearch while the system prompt, built from the registry, still describes it. — Register WebSearch before building the catalog (or append it to `catalog.names`), and assert it is in the first `meta` node.
8. **major** — `rolo_claude/config/plugins.py:136-148` — V2 `installed_plugins.json` values are read as dicts, but 2.1.281 writes an array of scoped install records per plugin (`plugins[id] = [{scope, projectPath?, installPath, version, …}]`, per the binary's own V1→V2 converter (an internal converter)), and V1 records use `installPath`, not `path`/`enabled`. — After a real `claude plugin install`, `entry` becomes `{}` and the root falls back to `plugins/cache/<name>`, but the real cache is `cache/<marketplace>/<plugin>/<version>`. So every plugin's MCP servers and its `hooks/hooks.json` are silently skipped (`build_hook_runner` uses the same `_plugin_roots`, without the `enabledPlugins` gate). The V2 test uses an invented `{installPath}` dict. — Iterate the record list, taking `scope == "user"` records plus project/local records whose `projectPath` matches cwd; read V1 `installPath`; pass `settings.raw` in `build_hook_runner`; and test with a manifest in the binary's shape.
9. **major** — `rolo_claude/commands/registry.py:155-202` (+`tools/skill.py:93`) + `mcp_setup.py:116-127`/`headless.py:277` — Two auto-mode restrictions remain. First, `` !`cmd` `` pre-execution (custom commands and the Skill tool) refuses, in every mode, any command not named in the command's own `allowed-tools` ("pre-execution command not permitted…"). It runs the rest via `subprocess.run(shell=True)` (dash on Kali, cmd.exe on Windows) with the harness's raw `os.environ`, provider keys included, and with no deny-rule or hook check. Second, the Chrome server's `skip_all_permission_checks` is fixed at spawn from the launch mode. — A skill whose `` !`git status` `` isn't in its frontmatter fails even in `bypassPermissions`; `[[ … ]]` fails on Kali; a session started in `default` and switched to `auto` with Shift+Tab still gets the extension's own permission prompt on browser actions. — Route `!` commands through `permission_engine.decide` (frontmatter `allowed-tools` as temporary allows) and the Bash tool's runner and env. Always spawn claude-in-chrome with `skip_all_permission_checks`, since rolo-claude's own engine already gates every `mcp__claude-in-chrome__*` call.
10. **major** — `rolo_claude/headless.py:510-523` + `cli.py:297-304` — `--input-format stream-json` reads stdin to EOF before running anything, then runs each line as a separate turn, one after another; the mid-turn steering the plan specifies for print mode does not exist. — An SDK-style client that writes one line and waits for the `result` before writing more deadlocks forever, and a correction sent during a turn becomes a new turn after it. — Read stdin on a thread, start the first turn on the first line, send lines that arrive while `session.busy` to `Session.steer` (otherwise queue them as turns), and test with stdin held open.
11. **major** — `rolo_claude/commands/builtins.py:71-90` + `tui/slash.py:22-24` + `tui/app.py:230` — In the TUI, `/compact` runs `session._run_compaction` to completion synchronously on the Textual event loop, and `_submit_prompt` dispatches slash commands even while a turn is running. — The TUI freezes (no repaint, no Esc) for the whole summarisation call. Typed mid-turn, it has the UI thread appending the marker and summary while the worker appends to the same log, so the marker can land between an assistant `tool_use` and its results. — Queue `/compact` as a worker `Command` handled between turns (reject or defer it while busy) and stream its `compaction` events.
12. **major** — `rolo_claude/tools/skill.py:104-121` + `commands/registry.py:137-152` — The Skill tool result never gives the skill's absolute directory (Claude Code starts it with "Base directory for this skill: …"). It lists sibling files as bare relative paths and leaves `${CLAUDE_SKILL_DIR}`/`${CLAUDE_SESSION_ID}` unsubstituted. — Skills that reference their own files (the Anthropic docx/pdf/pptx/xlsx skills read `*.md` references and run `scripts/…`) send the model to cwd-relative paths that don't exist, or to `${CLAUDE_SKILL_DIR}/scripts/x.py` with the variable unset. — Prepend the base-directory line, substitute the documented `${…}` variables in `expand_command_body`, and list siblings as absolute paths.
13. **major** — `rolo_claude/hooks.py:521-543` + `agent/loop.py:1444-1456,1472-1481` — PermissionRequest decisions are read from `hookSpecificOutput.permissionDecision`, but 2.1.281's schema is `hookSpecificOutput.decision.behavior`: `allow` with `updatedInput`/`updatedPermissions`, or `deny` with `message`/`interrupt` (binary). Also, PreToolUse `updatedInput` is applied after `decide()` has already checked the original input. — A Claude Code PermissionRequest auto-approve hook is ignored and the card still appears. A PreToolUse rewrite into a command that matches one of the user's deny rules is dispatched, even though deny rules are the only gate this harness keeps. — Parse `decision.behavior` (plus updatedInput and message), and re-run the deny/ask part of `decide` on the final input after any hook rewrite.
14. **major** — `rolo_claude/hooks.py:359-397,654-676,789-798` + `agent/loop.py:1794-1861` — The hook runner's process handling has five gaps: (1) hook children get the unstripped `settings.effective_env` with OPENROUTER_API_KEY, DATABRICKS_TOKEN and ANTHROPIC_API_KEY (the H2 must-do said "minus provider secrets, like tools"); (2) a timeout kills only the direct child, not its process group; (3) command and http hooks ignore Esc, and `_dispatch_tools` doesn't re-check `abort` after `_resolve_tool_call`; (4) the SessionEnd budget counts the implicit 600 s default, whereas the binary's (an internal function) counts only explicit `timeout` values and otherwise uses 1.5 s; (5) `shell: "bash"` runs `/bin/sh` on POSIX. — Esc during a slow PreToolUse hook does nothing until the hook returns, and then the gated Write runs anyway. Quitting with a SessionEnd hook that has no `timeout` can block for 60 s. `sh -c` grandchildren survive timeouts on Kali. A plugin hook can read every provider key. — Use `tool_child_env()`; kill with `start_new_session`+`killpg` on POSIX and `taskkill /T` on Windows; poll abort while waiting on hooks and re-check it before dispatch; size the SessionEnd budget from explicit timeouts only; use `/bin/bash` for `shell: "bash"`.
15. **major** — `rolo_claude/agent/loop.py:697-698,707-708,725-729,1021` + `providers/request.py:372-384,402-435` — Native Anthropic thinking and replay are broken in four ways: (1) `_step` reads `thinking_delta` from `delta["text"]` (the wire key is `thinking`) and logs `{"type":"thinking","text":…}`, which `build_anthropic_request_body` replays verbatim along with derive's non-wire `reasoning` key; (2) `budget_tokens` (24 000/32 000 for high/xhigh/max, at least 4 096 for any effort) is not kept below `max_tokens` (16 384 per turn, 4 096 for the summariser); (3) `message_start.usage` is ignored; (4) the H5 F rule that downgrades reasoning to text on a mid-session model change is not implemented. — Verified against `mock_anthropic`: request 2 replays `{'type': 'thinking', 'text': '', 'signature': 'SIG'}`, an invalid block with the thinking text lost, so every thinking+tool loop 400s. `--effort high` sends max_tokens 16 384 with a 24 000 budget and 400s on the first call.
