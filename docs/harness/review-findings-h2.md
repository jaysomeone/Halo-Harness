1. **critical** — `halo_harness/permissions.py:67-85,335-370,488-502,830-831` — Deny/ask Bash matching reuses the ALLOW normaliser (its keep-list never strips `PATH=`/`HOME=`/`GIT_*=`, its `\S*` value regex fails on `NAME="a b"`), never collapses whitespace (binary §4), classifies `x * y *` as a literal-star prefix instead of a wildcard ending `( .*)?` (§5), and PowerShell deny rules are never segment-split. — Verified in `auto` (deny rules are the only gate): `Bash(git push:*)` allows `GIT_SSH_COMMAND="ssh -i k" git push origin main` and `GIT_TERMINAL_PROMPT=0 git push`, `Bash(rm -rf:*)` allows `rm  -rf /tmp/x`, `Bash(rm:*)` allows `PATH=/usr/bin rm -rf x` and `FOO="a b" rm -rf x`, and `Bash(git push * --force *)` allows `git push origin --force`. — Build deny/ask candidates with a quote-aware tokenizer that drops EVERY leading `NAME=value` and the wrappers (plus `sudo`/`doas`/`env`), collapse whitespace before prefix tests, and compile any content with an unescaped inner `*` as a wildcard regex.

3. **critical** — `halo_harness/tools/edit.py:40-63,141-146` — The whitespace-tolerant fallback splices `new_string` over whole lines, including the last matched line's newline and the file's own indentation, and reports success. — Verified: `def f():\n    x = 1\n    y = 2\nz = 3\n` with `"x = 1\ny = 2"`→`"x = 10\ny = 20"` becomes `def f():\nx = 10\ny = 20z = 3\n` ("updated … (tolerant whitespace match)") — the exact path weaker models hit. — Replace only the content span (first non-blank char of the first line to the end of the last line's content), keep the newline and re-indent `new_string` by the file-vs-`old_string` indentation delta, or return the real near-match text as an error.
