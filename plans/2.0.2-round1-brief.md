## F. Terminal tab title says `halo`

- Confirm the mechanism first: child `claude` processes (auth status, mcp
  list, the cc: bridge) set the console title and leave it. On Windows the
  TUI should set the title through Textual (`App.title` is the window
  title; also emit OSC 2 `halo` to stdout when not under Textual's control)
  at start, on resume, after every `claude` child exits (hook the three
  spawn sites: `providers/cc_models.py`, `mcp/connectors.py` discovery,
  `agent/cc_process.py`), and on the drain tick that follows a child.
  Print mode: set `halo` at start and restore the previous title at exit
  (OSC 2 with the saved title when the terminal reported one; otherwise
  leave it). Windows: `ctypes.windll.kernel32.SetConsoleTitleW` as the
  fallback when OSC is not honoured (legacy conhost).
- Tests: a pilot test that the title is `halo` after a fake `claude` child
  (tests/helpers/fake_claude_cc.py) ran; a unit test for the print-mode
  save/restore sequence with a captured stdout.

## A. Roles v2

Current code: `halo_harness/roles.py` (`ROLE_NAMES` = orchestrator, coder,
reviewer, researcher, small; `resolve_role_table`, `resolve_role_ref`,
`parse_role_flag`, `describe_role_ref`, `format_roles_table`),
`config/agents_md.py` (built-in agent to role map), `agent/subagent.py`
(role resolution for the Agent tool), `commands/builtins.py::_cmd_roles`,
`headless.py` (role table at build), `team_config.py` (`roles` key),
`providers/effort.py` (`effort_set`, `sent_effort`, `requested_vs_sent`),
`tui/completion.py` (`complete_slash`, `complete_at_path`,
`current_token`).

1. ROLE_NAMES becomes orchestrator, planner, coder, reviewer, judge,
   researcher, tester, compaction, small, subagent_default. Wire: the Plan
   agent type resolves through `planner`; `compaction` is the rung after
   `compactionModel`; `subagent_default` is the last rung before the
   session model for any sub-agent with no role; `Judge` and `Tester`
   join the built-in agent map with one-paragraph system prompts (judge:
   adjudicate candidate outputs or verify results against acceptance
   criteria, answer pass/fail with reasons; tester: run the named suites
   and live checks and report results verbatim). Every existing test that
   enumerates ROLE_NAMES must be updated, not loosened.
2. Per-role effort: a role value is a bare model string or
   `{"model": ..., "effort": ...}` in config.json `roles`, team.json
   `roles`, `--role NAME=MODEL[:EFFORT]` and templates. `resolve_role_ref`
   returns model and effort; sub-agent runs apply the role's effort through
   the same path the session uses (`agent/loop.py` set_model / effort),
   resolved with `providers/effort.py` so an unsupported level maps the way
   the session does. `/roles` and `halo stats --roles` show model, effort
   as `requested (sent as X)` when they differ, and price.
3. Custom role names: any `[a-z][a-z0-9_]*` defined in a template or
   team.json is a valid role for `Agent(role=...)`, `--role`, frontmatter
   `role:`; an unknown name errors with the list of known names.
4. TUI tab completion: `/role <name> <model> [effort]` (new, sets one
   role for this session) and `/roles set <name> <model> [effort]`
   complete role names, then model refs from `controller.list_models()`
   (prefix first, then substring), then the effort levels valid for that
   model (`effort_set`). Put the ranking in `tui/completion.py::
   filter_items(items, prefix)` and reuse it. Shell completion: `halo
   completion bash|zsh|powershell` prints a script that completes
   subcommands, role names and the cached model refs (read from the
   state dir's catalog cache, no network).
5. Templates: `~/.halo/roles/<name>.json` = `{"name", "description",
   "roles": {role: {"model", "effort"}}}`. `/roles templates`, `/roles save
   <name>`, `/roles load <name>`, `/roles new <name>`, `/roles edit <name>`
   (a TUI form in `tui/dialogs/roles_editor.py`: one row per role with a
   model picker reusing the /model list and an effort selector; `$EDITOR`
   when `roles.editor: "external"` is set), and CLI `halo roles template
   list|save|load|new|edit|show`. Precedence: CLI `--role` > loaded
   template > team.json > config roles > defaults; write it in
   `docs/ROLES.md` (new) and link it from docs/COMMANDS.md and HANDBOOK.
