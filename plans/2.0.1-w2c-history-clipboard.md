## 1. Up-arrow recall: the merged history sorts by mixed timestamp units

Verified on the Kali VM: Claude Code's `~/.claude/history.jsonl` stores
`timestamp` in MILLISECONDS (1790623928405); halo's `~/.halo/history.jsonl`
stores SECONDS (1790882425.67, `history.append_history_entry` uses
`time.time()`). `history.load_merged_history` sorts both files' entries by
the raw value, so every Claude Code entry sorts after every halo entry and
Up recalls the last `claude` prompt for that directory, never the one just
typed in halo.

- `load_merged_history`: normalise at read time (a value above 1e11 is
  milliseconds, divide by 1000), sort by the normalised seconds, and on
  equal seconds keep halo's own entries last (they are the ones typed
  here). `append_history_entry` writes MILLISECONDS from now on (Claude
  Code's own schema), and reading accepts both units forever.
- The in-memory cache in `tui/app.py::on_prompt_input_history_nav` is
  rebuilt after every submit (already) and also after a steer submit and
  a slash-command submit (check both paths reach the same append).
- Up on an empty first line recalls the newest entry; with text typed on
  the first line, Up walks only entries that start with that text (prefix
  filter, Claude Code behaviour); Down past the newest restores the draft.
- Tests: a merged history with a ms Claude entry newer than a seconds halo
  entry and an older ms Claude entry, asserting the recall order newest
  first by real time; the append writes ms; both units read back; prefix
  filter; draft restore; a pilot that submits, then presses Up and sees
  that exact prompt.

## 2. Copy inside the chat box

`app.py::action_interrupt_or_quit` copies `screen.get_selected_text()`
when a selection exists, but a selection made inside the prompt
`TextArea` (mouse drag or Shift+arrows) is the widget's own
`selected_text`, which that call does not return, so Ctrl+C in the chat
box arms quit instead of copying.

- Ctrl+C: if the prompt input has focus and `prompt_input.selected_text`
  is non-empty, copy that (OSC 52 plus the external-tool fallback already
  in place) and notify `Copied N characters`; otherwise the existing
  screen-selection copy; otherwise the existing interrupt / double-press
  quit.
- Ctrl+X cuts the input selection the same way; Ctrl+A selects all text
  in the input (TextArea bindings).
- Transcript: confirm mouse-drag selection works on every transcript
  widget (AssistantText, ThinkingBlock, tool cards, the phase line) and
  that Ctrl+C copies it; a tool card's `o` pager keeps its own copy key.

## 3. Paste

The terminal's paste (bracketed) already reaches `PromptInput._on_paste`;
what fails for rolo is middle-click / right-click paste (the TUI captures
the mouse) and Ctrl+V on Linux terminals (a plain control character
there).

- Ctrl+V in the prompt input reads the system clipboard through the
  external tools the clipboard backend already knows (`xclip -o` or
  `xsel -o`, `wl-paste`, `pbpaste`, PowerShell `Get-Clipboard` on Windows)
  in a worker and inserts the text through the same paste path (so the
  4-line placeholder rule applies). With no tool available it notifies
  `Paste with your terminal's shortcut (Ctrl+Shift+V) or Shift+middle-click`.
  Never block the UI thread on the tool.
- Bracketed paste stays the primary path and is unchanged.
- Docs: a "Copy and paste" entry in docs/TROUBLESHOOTING.md and the
  keyboard help (`?`/F1): select with the mouse and Ctrl+C copies; Shift
  while dragging gives the terminal's own selection; paste with
  Ctrl+Shift+V on Linux terminals, Ctrl+V in Windows Terminal, Shift +
  middle-click, or Ctrl+V in the chat box when a clipboard tool exists.
- Tips (W2b's `tips.py`): two tips for copy and paste with these keys.
- Tests: Ctrl+C with an input selection copies and does not arm quit
  (clipboard backend stubbed); Ctrl+C with no selection keeps today's
  behaviour; Ctrl+X cuts; Ctrl+A selects all; Ctrl+V with a stubbed tool
  inserts the text and applies the placeholder rule for 4+ lines; Ctrl+V
  with no tool notifies; the help text lists the keys.
