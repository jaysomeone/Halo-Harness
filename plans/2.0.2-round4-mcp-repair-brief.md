The owner's complaint (Kali VM, 2026-10-02): "I see the mcps but there is
no reconnect or reauth or any way to fix these things." Today
`tui/dialogs/mcp_status.py` lists servers and connectors with a status and
the explain-the-zero text; the only actions are reconnect (via the
controller's `reconnect_fn`) and the generic `halo mcp login`. This round
turns the dialog into the repair surface.

## What to build

1. The `/mcp` dialog shows its key legend at the bottom and gains the
   actions, each acting on the highlighted row: `r` reconnect, `R`
   reconnect all, `a` approve (a project `.mcp.json` server awaiting
   approval), `l` login (the OAuth flow from 2.0.1 for http/sse servers
   that answered 401 or declare OAuth; for a claude.ai connector, show the
   re-auth instructions line already produced by the bridge), `L` the
   server's log tail (`~/.halo/mcp/<server>.log`; create the per-server
   log in `mcp/manager.py` if it does not exist yet: stderr of a stdio
   server and connect/transport errors, rotated at 1 MB), `e` edit the
   entry (open the source file that defines it at that server's line in
   `$EDITOR`; with no `$EDITOR`, an inline form for command/args/env/url/
   headers that writes back to the same scope file), `i` install hint for
   a command-not-found (`npx`, `uvx`, `pipx`, `uv tool`, `pip`, `node`
   guessed from the command and args, shown as a copyable line), `d`
   disable or enable (per scope, the way Claude Code's `disabledMcpServers`
   works), `t` test (a `tools/list` round trip with timing, result shown
   in the row). Every failed row carries the reason and the one fix line
   `doctor` already computes; reuse that code, do not duplicate it.
2. Servers that die mid-session reconnect on next use with backoff
   (1, 2, 4, 8 s, then every 30 s, stop after 10 minutes); the row shows
   the attempt count and next retry; `R` resets the backoff.
3. `halo mcp fix <name>` runs the same diagnosis from the CLI: prints the
   reason, the fix line, and offers the matching action (`--apply` runs
   it non-interactively: reconnect, install hint printed, login started,
   or edit opened). `halo mcp test <name>` is the `t` action from the CLI.
4. Docs: docs/COMMANDS.md (`/mcp` keys, `halo mcp fix|test`),
   docs/TROUBLESHOOTING.md ("an MCP server shows failed" walkthrough),
   CHANGELOG [2.0.2] item.

## Tests

Pilot tests for each key against the fake MCP servers in tests/helpers
(a stdio server that dies on demand for reconnect/backoff, a 401 http
server for `l`, a missing command for `i`, a project `.mcp.json` pending
approval for `a`); unit tests for the install-hint guesser, the log
rotation, the backoff schedule and the scope-aware disable; CLI tests for
`halo mcp fix` and `halo mcp test` with and without `--apply`. Verify with
the three suites from the repo root with PYTHONPATH set, then `git
checkout -- docs/harness/tui-snapshots`; report the three RESULT lines.
