# Halo 2.0.2 round 3 (C): sub-agent visibility and scale

Read plans/WORKER-RULES.md first and follow it exactly (writes of 250 lines
or fewer per call, no sub-agents, hermetic tests scoped with
BRIDGE_TEST_HOME / BRIDGE_STATE_DIR, hand-back format RESULT LINES / FILES
TOUCHED / WHAT YOU FOUND, no commit, no push). The design is
plans/2.0.2-brief.md section C; rounds 1 and 2 landed roles v2
(docs/ROLES.md) and organizations (docs/ORGS.md, `halo_harness/orgs.py`),
so an org run already produces a tree of sub-agents with titles and

sub-agent cards (`tui/widgets/cards.py`). Never add safety, refusal or

file.

## What to build

1. The tasks panel: `/tasks` and Ctrl+T open `tui/dialogs/tasks.py`, a
   full-height panel listing every running, queued and finished sub-agent
   and background Bash job of this session: position or role, model,
   phase (the W2b phase words), elapsed, tool-call count, cost so far,
   and for an org run its place in the tree (indented under its parent).
   Enter on a row opens a live transcript viewer of that agent's
   `subagents/agent-<id>.jsonl` (follow mode by default, PgUp/PgDn, `o`
   opens the pager, Esc back to the list); finished agents stay listed
   for the session with their final status and result size. The panel
   refreshes from the same event stream the dock uses (TaskCreated,
   TaskCompleted, phase and tool events carry `agent_id`); Ctrl+T again or
   Esc closes it. The status bar shows `agents N` (running count) when
   N > 0.
2. Scale: config `agents.max_concurrent` (default 4, any positive int) and
   `agents.max_depth` (default 1, up to 3); an org may override both.
   Beyond the concurrency cap, spawns queue (status "queued" in the panel)
   and start as slots free. The Agent tool accepts `count` (N identical
   prompts) and `batch` (a list of prompts, each with optional
   role/model/effort); the parent waits on all children and gets one
   combined result with one section per child, in spawn order. The
   orchestrator system prompt says the model may spawn several agents in
   one call and that `/tasks` shows them.
3. Shared task board: `TaskCreate`, `TaskUpdate`, `TaskList` tools backed
   by the session (`~/.halo/sessions/<id>/tasks.json`; fields id, title,
   status open|claimed|done|blocked, owner agent, notes, result pointer);
   sub-agents of the same session share it, so an org's workers can claim
   and report work. The tasks panel shows the board in a second tab.
4. Docs: docs/SUBAGENTS.md (panel keys, config, `count`/`batch`, the task
   board), linked from docs/COMMANDS.md and docs/HANDBOOK.md; CHANGELOG
   [2.0.2] item.
