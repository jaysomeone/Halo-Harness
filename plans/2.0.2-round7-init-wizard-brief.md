## Why it feels wrong today

`halo init` runs `tui/dialogs/init_tabs.py::InitTabsApp` as its own
Textual app for the provider tabs; Esc is bound to "finish", which exits
that app, and `init_cli.py` then continues with plain console prompts
(`_step_finalize_default_model`, `_step_pick_permission_mode`,
`_step_linux_fixes`, `_step_summary`). So the user sees a full-screen
dialog, has to press Esc to leave it, the screen tears down, and the next
section appears as console text. Nothing says "Next".

## 1. One wizard, explicit navigation (`tui/dialogs/init_wizard.py`, new)

- One Textual app for the whole interactive init, with a header `Step N of
  M: <name>` and a footer row of buttons: `Back`, `Skip`, `Next` (primary),
  and on the last step `Finish`. Enter on a focused button activates it;
  Ctrl+N / Ctrl+B also move; Esc asks "Quit setup? What you saved so far
  stays" (y/N) instead of silently ending. Each step is a Screen pushed and
  popped inside the same app; nothing exits to the console between steps.
- Steps, in order: 1 Providers (the existing tabs content, unchanged
  behaviour, moved into a step), 2 Default model and effort (the picker
  the console step used, now a list in the wizard), 3 Permission mode,
  4 Theme (owner 2026-10-03: the list of built-in themes with a live
  preview of the transcript and status bar in each; writes `theme`; the
  DOOM theme joins this list in 2.0.7), 5 Roles (new, below), 6
  Organizations (new, below), 7 Linux fixes (only when `_step_linux_fixes`
  has something to offer; otherwise skipped automatically), 8 Summary
  (what was written, the doctor lines, "Run it from any directory: halo",
  `Finish`).
- Modes (owner 2026-10-03): the Roles and Organizations steps each start
  with an on/off switch, `roles.enabled` and `orgs.enabled` (default on
  for roles, off for orgs). Off means: every role resolves to the session
  model, `/roles`, `/role`, `/org`, `/tasks`' board tab and their tips are
  hidden from the slash menu and the rotating tips, and the Agent tool
  does not advertise `org=`; on means the rest of the step applies
  (template, then optionally the definitions editor). The switches are
  also plain config keys and `/setup` flips them later.
- `init_cli.py` keeps its non-interactive paths (`--yes`, `--provider`,
  no TTY) byte for byte; the interactive path calls the wizard and reads
  its results the way `_run_init_tabs` does today. The wizard app can also
  be started at any step (`start_step=`), which items 2 and 3 use.

## 2. Roles step and the setup screen

- Step 5 shows (when roles mode is on): a short explanation (one paragraph: roles decide which
  model does what; the session model is used when a role is unset), a
  template list to pick from (`~/.halo/roles/*.json` plus three shipped
  presets written on first use and never overwritten: `balanced` (the
  cost-aware defaults), `quality` (the session model everywhere, judge and
  reviewer on the strongest configured model), `local-first` (small,
  researcher and judge on a local `ol:` model when one is configured,
  else the cheapest configured model)), a preview of the chosen template's
  table, and buttons `Use this template`, `Edit roles...` (opens the round
  1 roles editor form inside the wizard and returns), `Skip for now`.
  Skipping leaves the defaults and prints the one line `/roles` hint in the
  summary.
- The same screen is reachable later: `/setup roles` in the TUI and
  `halo setup roles` on the CLI (the CLI opens the screen in its own app
  when there is a TTY, else lists the templates). `/roles` and `/role`
  with no arguments mention `/setup roles` in their first line.
- The roles editor (round 1) gains the template picker at its top (choose
  a template, the form prefills; `Save as template...` at the bottom).

## 3. Organizations step and the setup screen

- Step 6 shows (when orgs mode is on): one paragraph (an organization is a tree of positions that
  runs as sub-agents; most people start with `solo` or `release-flow`), the
  list of built-in and saved orgs with the tree preview of the highlighted
  one, and buttons `Make this the default org` (config `orgs.default`,
  used by `/org run` with no name), `Edit org...` (the round 2 org editor
  inside the wizard), `Skip for now`.
- Reachable later as `/setup orgs` and `halo setup orgs`; the org editor
  gains the same template picker at its top ("start from: solo /
  release-flow / company / <saved>").
- `halo setup` with no argument opens the wizard at step 5 (roles), then
  6 (orgs), then summary: the "set up roles and orgs later" path the owner
  asked for; `/setup` in the TUI does the same inside halo (the wizard
  runs as a modal screen stack over the session, and the session picks up
  the new role table and default org without a restart).

## 3b. Ideas borrowed from Paperclip (owner 2026-10-03: "that tool has lots of good ideas")

Paperclip (an open-source "run an AI company" orchestrator) models an org
chart for agents with reporting lines, budgets, goals, an issue tracker
with atomic task checkout, approval gates, scheduled heartbeats, ready-made
team templates with preview and install, export/import with secret
scrubbing, and a CLI-first `onboard` flow. What fits Halo now, in this
round or the orgs feature it extends:

- Ready-made org templates with preview and install: the Organizations
  step's list IS this; add `halo org install <name>` and `/org install`
  for a template shipped in the package or saved by the user, and an
  `orgs/README` line per template (what it is for).
- Budgets: `budget_usd` on an org (hard stop) and per position (warning at
  80 percent, hard stop at 100), enforced through the existing cost meter;
  the run ends with a clear "budget reached" result and the dock shows the
  remaining budget while an org runs.
- Goals: `/org run <name> "<goal>"` records the goal on the task board as
  the root task; positions' tasks link to it (`parent`), so the board tab
  shows goal -> tasks -> results.
- Approval gates: a position may carry `requires_approval: true`; its
  result is held as a pending card (the W3a dock) for the user to accept,
  edit the instruction and re-run, or stop, before the parent continues.
- Atomic task checkout: the round 3 task board's claim already does this;
  document it in those terms.
- Export and import: `halo org export <name>` / `import <file>` for orgs and
  role templates (plain JSON; they hold no secrets, so no scrubbing needed,
  but the import validates role names and reports).
- Persistent work context: an org run writes its goal, positions, task
  board and results under the session, and `/org resume` continues an
  interrupted run from the board.

Later, recorded in the roadmap, not this round: scheduled routines and
heartbeats (cron, webhook and API triggers that start an org run), other
agent runtimes as positions (Codex, Gemini CLI, OpenCode: the 2.0.4 Codex
route makes the first one possible), a web dashboard, and Paperclip's
private LAN/Tailscale mode, which belongs to the 3.0.1.1 research.
