## What to build

1. `halo_harness/orgs.py`: an organization is a tree of positions saved as
   `~/.halo/orgs/<name>.json` `{name, description, positions: [{title,
   role|model, effort, instructions, tools?, reports: [title, ...]}]}`
   with exactly one root (a position nobody reports to). Load, validate
   (unknown role names and dangling `reports` error with the list of known
   names), save, list, and `describe(org)` for a text tree. Built-in
   templates shipped in the package and copied into `~/.halo/orgs/` on
   first use (never overwritten once present): `solo` (orchestrator only),
   `release-flow` (orchestrator writes a brief -> implementer works in
   250-line writes -> tester runs the suites -> reviewer lists findings
   -> fixer applies them -> tester again -> orchestrator reports; use the
   hand-back format from plans/WORKER-RULES.md as the position
   instructions), `company` (CEO -> VP Engineering, VP Marketing, VP
   Research -> one manager each -> two workers each; sensible roles,
   empty instruction slots).
2. Running one: `/org run <name> "<goal>"` and `Agent(org="<name>",
   prompt=...)`. The root position becomes a sub-agent whose system prompt
   is its instructions plus a rendered view of the tree and of the
   positions it may delegate to; it delegates through the existing Agent
   tool with `role`/`model`/`effort` fixed per position (a child may only
   spawn its own `reports`); results flow back up as ordinary sub-agent
   results. Depth comes from the tree; concurrency from
   `agents.max_concurrent` (config, default 4) unless the org sets
   `max_concurrent`. The dock shows each running position as
   `<title> (<role>)`.
3. Editing: `/org list|show|new|edit|load|run` and CLI `halo org
   list|show|new|edit|run <name> "<goal>"`. `/org edit` reuses the roles
   editor form family (`tui/dialogs/`): a tree view on the left, the
   selected position's fields on the right (title, role or model picker,
   effort selector, instructions text, reports multi-select); `$EDITOR`
   when `roles.editor: "external"`. `/org show` prints the text tree.
4. Docs: `docs/ORGS.md` (schema, the three built-ins, how a run flows,
   limits), linked from docs/COMMANDS.md and docs/HANDBOOK.md; CHANGELOG
   [2.0.2] item.
