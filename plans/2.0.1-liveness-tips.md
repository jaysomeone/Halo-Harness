## Part A: liveness. Something visible changes every second while a turn runs

A1. Phase line. One live transcript line per model call, mounted when
the request is sent and updated in place at least once a second by a
TIMER (the drain timer), never only on chunk arrival:

- `✻ Sending request to <model label>…` until response headers arrive
- `✻ Thinking… (12 s, no tokens yet)` headers in, no chunk yet
- `✻ Thinking… (18 s · 412 reasoning tokens)` once reasoning deltas
  arrive, in ANY wire shape: `reasoning_content` deltas (DeepSeek, Kimi,
  GLM), OpenRouter `reasoning` / `reasoning_details`, Anthropic thinking
  deltas, Databricks `{"type":"reasoning","summary":[...]}` blocks
- `✻ Writing… (23 s · 1.2k tokens)` once text or a tool call streams;
  the line stays above the streaming text until message_end
- on message_end it collapses to `✻ Thought for 18 s (412 tokens)` when
  there was reasoning, or is removed when there was none; Ctrl+O
  (verbose) expands the full reasoning text under the summary
- after tool results are sent back: `✻ Waiting for model… (3 s)` until
  the next first chunk
- after 30 s with no chunk the line gains the dim suffix
  ` · no data for 30 s, Esc interrupts, typing steers`, refreshed every
  10 s (`40 s`, `50 s`, ...) until a chunk arrives

A2. Live reasoning preview. While reasoning streams, the ThinkingBlock
shows the LAST THREE lines of the reasoning (dim italic, wrapped to the
width, updated at the drain rate), not one line. It is expanded during
streaming and collapses to the A1 summary on completion (stays open
under Ctrl+O). Reasoning that arrives only with the final chunk
(Databricks GLM when the gateway does not stream it) is shown as the
collapsed summary at that moment; the A1 elapsed counter is the live
signal in that case.

A3. Status bar. While a turn runs the right-hand cluster shows the phase
word, the elapsed seconds and a received-token counter that increments
as chunks arrive: `⠋ thinking 18 s · ↓412`, `⠙ writing 23 s · ↓1.2k`,
`⠹ tool Bash 4 s`, `⠸ waiting 3 s`. The spinner frame and the elapsed
value change at least once per second, so a frozen UI is distinguishable
from a silent model. After turn_done the cluster returns to idle (this
is also where the stuck-glyph defect from the gap list gets its reset).

A4. Tool cards. A running card shows elapsed seconds in its header
(`⏺ Bash(pytest -q) · 12 s`) and its last streamed output lines (Bash
already streams tool_progress; Grep, Glob, WebFetch, MCP and Agent calls
show at least the elapsed counter).

A5. Sub-agents. The parent's nested card shows the child's phase and
tool count live: `agent reviewer · thinking 9 s · 3 tools`.

A6. Telemetry. Each model call records in the session log: `ttfb_ms`
(headers), `first_reasoning_ms`, `first_text_ms`, `reasoning_streamed`
(bool). `stats --models` shows "reasoning streamed" as a percentage per
model so rolo's work-VM data tells us which gateways stream reasoning
(feeds GLM-brief change 6 and the FAMILY-BASELINE doc).

A7. Print mode is unchanged (no progress noise on stdout; `--verbose`
stream-json already carries the deltas).

A8. Docs: `docs/TROUBLESHOOTING.md` "Is it frozen?" entry describing the
phase line, the counters and what each state means; README screenshot
text updated if it names the old indicator.

## Part B: rotating tips in the input placeholder

B1. New module `halo_harness/tui/tips.py`: `Tip(text, needs=())` and
`TIPS`, about 40 curated tips (each at most 96 chars, imperative, no
filler), plus GENERATED tips for every slash command in the registry
that no curated tip covers: `/name <argument-hint>: <description>`
(description cut at 70 chars), including custom commands and skills
discovered for the cwd. `needs` names a provider or feature
(`"cc"`, `"dbx"`, `"or"`, `"chrome"`, `"mcp"`) and the tip is shown only
when it is enabled or present.

B2. Rotation: a random tip at launch; the next tip (shuffled order, no
repeat until the list is exhausted) at every turn_done and every 15 s
while the input is empty and no turn is running; never change while the
input has text or while a turn runs. Placeholder format `Tip: <text>`,
fitted to the input width minus 6 with an ellipsis.

B3. Off switch: `tips: false` in `~/.halo/config.json` or `HALO_TIPS=0`
(BRIDGE_/ROLO_CLAUDE_ names via env_compat) gives the static placeholder
`Ask anything · / commands · @ files · ! shell`. The old "try read
README.md and summarize it" text is removed everywhere (grep the tree,
docs and tests for it).

B4. `/tips` prints every applicable tip to the transcript as a list;
`/help` lists `/tips`.

B5. Tips may only name things that exist. A test parses every `/word`
token in every tip and asserts it resolves to a built-in command, every
`--flag` token is a real cli flag outside the not-yet list, every
`Ctrl+X`/`Shift+Tab` names a bound key, no tip is 97 chars or longer, no
tip mentions `rolo-claude`, and none contains safety/refusal wording.

B6. Tests: launch tip differs from the after-turn tip (seeded RNG); idle
rotation with the 15 s timer shrunk by a seam; no change while typing;
no change during a turn; the config and env off switches; generated tips
cover every built-in command; width fitting; `needs` filtering (a `cc`
tip hidden when cc is not enabled).

Curated draft (the worker keeps only the ones that exist in this tree,
corrects wording against the real command and key names, and adds the
rest from the registry):

- `/model` opens the picker: arrows move, Enter selects, type to filter; `/model <ref>` switches directly
- `/models refresh` re-reads every provider's catalog: prices, context, new models
- `/effort` sets thinking depth; GLM on Databricks has low, high and max
- Shift+Tab cycles permission modes: default, acceptEdits, plan, auto
- Type while a turn runs to steer it; the model changes direction at the next chunk
- Esc interrupts the current step; Ctrl+C twice quits
- `@path` mentions a file in your prompt; Tab completes the path
- `!cmd` runs a shell command and puts its output in the prompt
- `/rewind` undoes a step's file changes
- `/compact [focus]` summarises the conversation to free context
- `/stats --models` shows per-model edit failures, tool errors, cost and time to first token
- `/improve` drafts memory and rule candidates from recent failures; you approve each one
- `/providers` shows which providers are enabled and why
- `/mcp` lists MCP servers and reconnects one
- `/memory` opens the auto-memory directory
- `/resume` picks an earlier session; `halo -c` continues the last one
- `/doctor` checks install, credentials and tools
- `/init` sets up a provider step by step
- `/cost` shows tokens and spend for this session
- `/theme` switches themes, saved in ~/.halo/config.json
- `/intro` replays the launch intro
- Ctrl+O toggles verbose: full thinking and tool output
- Ctrl+R searches prompt history
- Paste 4 or more lines and it becomes a `[Pasted text #1]` placeholder
- `halo -p "prompt"` prints an answer without the TUI; `--output-format json` for scripts
- `halo --chrome` connects the Claude in Chrome extension; `--playwright` adds browser tools
- `/plan` enters plan mode: read-only until you approve the plan
- `/agents` lists sub-agents; `@agent-<name>` runs one
- `/skills` lists skills; `/<skill-name> args` runs one
- `/permissions` shows the allow, deny and ask rules from your settings
- `/context` shows what is in the context window right now
- `/export` writes the transcript to a file
- `/add-dir` adds a working directory for this session
- `halo stats --since 7d` summarises the week's sessions
- `--effort high` on the command line sets the starting effort
- `/dbx` lists Databricks endpoints
- `/zdr` keeps OpenRouter requests on zero-data-retention providers
- `/fast` sorts OpenRouter providers by throughput

## Part C: effective values (approved 2026-10-01, ships with Part A in W2)

Never show a control value the gateway will silently change. Every
place a value is shown or chosen shows the value actually sent:
- the `/effort` card marks a clamped choice inline, for example
  `medium (sent as high on this route)`, and the confirmation line after
  a change names the sent value;
- the status-bar effort chip shows the SENT value;
- `/status` and `/context` list the request parameters that the route
  changed (effort, temperature clamp, max_tokens clamp, dropped fields
  from learned rules) as `requested X, sent Y`;
- the stream-json `system/init` line carries `effort_sent` next to the
  requested effort;
- tests: a GLM route with `--effort medium` shows `sent as high` in the
  card, the chip and the init line; an Anthropic route with `xhigh` on a
  model that lacks it shows `sent as max`.
