## What the governor is (from the report)

One shared, adaptive limiter per gateway HOST (bucket key =
`urlparse(base_url).netloc`, provider name only for keyless/local kinds),
visible to every halo process on the machine, with five properties:
cross-process state on disk under a lock; AIMD (an overload status 429,
529, 500, 502, 503, 504 cuts `rate *= backoff_mult` and sets a cooldown
honouring `Retry-After`, else `cooldown_base * 2^(n-1)` capped at 2^6;
`ramp_after` consecutive OKs add `ramp_inc` back toward the ceiling, never
below `rate_floor`); a hard cross-process in-flight cap with dead-pid and
stale-entry reaping; priority fairness (orchestrator 0, judge and writer
1, worker 2, FIFO within a level); a per-gateway jsonl log with
`inspect`, `inspect_all`, `recent_calls`, `health`. Token bucket for
pacing plus the hard in-flight cap. Fail-open is one half-open probe for
the front-of-queue waiter after `max_wait`, never a bail-out. Transport
errors release the permit without cutting the rate; the second-generation
port also counts caller-side timeouts as rate-cutting events and warns
loudly when state cannot persist. `governed(key, params, do_call, ...)`
wraps acquire, call, report and transparent retry (up to `max_retries`).
`routing.py` picks WHICH gateway per role from `fallbacks[role]` (different
hosts), classifying each with `health()`: `open` (cooldown over 8 s or 3
consecutive errors) is skipped, `degraded` usable, `ok` preferred; when
all are open, the least-cooled one wins.

## 1. Port into `halo_harness/providers/governor.py` and `providers/gateway_routing.py`

- Keep the algorithm and the public API shape (`key_for`, `acquire`,
  `report`, `governed`, `inspect`, `inspect_all`, `recent_calls`,
  `health`), stdlib only. State under `<state dir>/governor/` (the Halo
  state dir, so `BRIDGE_TEST_HOME` / `BRIDGE_STATE_DIR` scope it in tests).
- Improvements to make while porting (this is the owner's "make edits to
  make it better"):
  1. Cross-platform locking: the original uses `fcntl.flock`; Windows has
     none. Use `msvcrt.locking` on Windows and `fcntl` elsewhere behind one
     `_locked(path)` context manager, with a lock-timeout and a loud
     stderr warning plus `governor_state_unpersisted` telemetry event when
     locking or writing fails (the port's "loud warning" idea), never a
     silent in-memory fallback without that warning.
  2. `pid_alive` from the existing `bg_run.pid_alive` (zombie-aware,
     Windows-aware) instead of a raw `os.kill(pid, 0)`.
  3. Clock: monotonic time for pacing within a process, wall time only for
     the on-disk cooldown timestamps, and tolerate clock skew between
     processes (a cooldown in the future beyond its own maximum is clamped).
  4. `Retry-After` parsing handles both delta-seconds and HTTP-date, and
     caps at a configurable maximum (default 120 s).
  5. Atomic state writes (temp file plus `os.replace`), a schema version in
     the state file, and recovery from a corrupt file (reset with a warning
     rather than a crash).
  6. Log rotation for the per-gateway jsonl (1 MB, like the MCP logs).
  7. Caller-side timeouts count as overload only after two in a row
     (one timeout is a network blip, two is a struggling gateway).
  8. Priority comes from the caller's role: orchestrator and the main
     session 0, judge, reviewer, tester and planner 1, every other
     sub-agent 2; configurable `governor.priorities`.
- Config (`governor.*` in config.json, per host overrides under
  `governor.hosts.<netloc>`): `enabled` (default true), `rate_rps` 8.0,
  `burst` 8, `max_inflight` 6, `rate_floor` 0.25, `ramp_after` 5,
  `ramp_inc` 0.5, `backoff_mult` 0.5, `cooldown_base` 2.0, `max_wait` 120,
  `max_retries` 5, `retry_after_cap` 120.

## 2. Integrate at the HTTP layer

Every remote model request (Databricks, OpenRouter, Anthropic native, and
the `ol:` route when 2.0.3 lands) goes through `governed()` with a
`do_call` closure in `providers/http.py` (one place), carrying the
session's role and agent id. The existing retry ladder in `agent/loop.py`
stops retrying overload statuses itself for governed routes (the governor
owns that), keeps retrying everything else, and the W2 "steer restart"
counter stays separate. The TUI status bar shows `gov 4.0 rps / cooldown
12 s` in the overflow cascade when a bucket is below its ceiling; `/gov`
(and `halo gov`) prints `inspect_all()` and the recent calls of one host;
`halo doctor` shows each known gateway's health.

## 3. Failover to a different host

`gateway_routing.choose(role, candidates)` from the port, wired into the
2.0.1 fallback-model mechanism: `fallback_models` entries whose host is
`open` are skipped, the least-cooled wins when all are open, and the
notice names the health that caused the switch. `roles.<name>.fallbacks`
(list of model refs on OTHER hosts) feeds the candidates per role; the
docs say plainly that a fallback on the same gateway host does not help
and the config loader warns when one is configured.

## 4. Lanes (the owner's standing role split)

A lane is a role-to-tier assignment with a rule: tiers are declared per
model in the model table (`tier`: 1 strongest ... 3 cheapest, with sane
defaults for the known families), `roles.lanes` maps roles to the model
tier they may use (defaults: coder tier 2 or better, reviewer, judge and
tester never weaker than coder, researcher and small tier 3 allowed, a
"huge-context" lane for diff-heavy work picks the largest-context model
available), and the roles table validator refuses a configuration where
the verifier roles (reviewer, judge, tester) resolve to a weaker tier than
coder, with one line saying which role to raise. Local Ollama models slot
into tiers 2 and 3 when 2.0.3 adds them; until then the lane rule applies
to the configured routes.
