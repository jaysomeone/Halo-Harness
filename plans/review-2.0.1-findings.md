# Halo Harness 2.0.1 release review (v2.0.0 `b89d6d6`..`183a53a` + uncommitted part 11)

Scope: `git diff b89d6d6 -- halo_harness scripts pyproject.toml` (98 files) including the uncommitted part-11 working-tree changes, read file by file against the part 1-10 commit messages. Line numbers refer to the working tree as of 2026-10-03. "Verified" means reproduced with a scratch script on this Windows 11 host (Python 3.11, `PYTHONPATH=<repo>`, `BRIDGE_TEST_HOME` pointed at a temp fake home built with `tests/helpers/fake_home.py`, provider variables scrubbed, the mock upstream from `tests/helpers/mock_openai.py` where a model call was needed), or traced through the code where a run was impractical. No test suite was run, no repo file was edited, and no real `claude` process or real key was used. Part 11 was being written while this review ran. One bug I reproduced (a fresh TUI never started claude.ai connector discovery because the auth cache was cold when `build_controller` ran) was fixed in `tui/app.py`/`tui/bootstrap.py` during the review, so it is not listed. Binding constraints (no safety/refusal logic; auto mode allows everything except the user's own deny/ask rules) are respected throughout: nothing below proposes gating behaviour.

Counts: 2 critical, 16 major, 20 minor.

## Findings

1. **critical** — `halo_harness/headless.py:1508-1525` + `headless.py:1042-1052` — `--no-session-persistence` unlinks whatever log the run opened, drops its index entry and rmtrees its session dir. Combined with `-c`, `--resume <id>` or `--session-id <existing>`, it deletes the pre-existing conversation: its transcript, its sub-agent logs and its rewind shadow repo. — Verified: mock-upstream run of `halo -p ...`, then `halo -p -c --no-session-persistence ...`. The first session's `.jsonl` existed after run 1 and was gone after run 2. — Fix: delete only a log this process created. Record "file existed / id came from -c/--resume/--session-id/--fork" before `SessionLog(...)`. For a resumed log, truncate back to its pre-run byte length, or reject the flag combination with exit 2.
2. **critical** — `halo_harness/tui/bootstrap.py:55-87` + `headless.py:1209-1229` — The TUI calls `build_session` without `cli_flags`, and so do `--ax-screen-reader` and the `--tmux` re-exec, which reuse `build_controller`. Every new 2.0.1 flag is therefore accepted and silently ignored interactively: `--restricted` keeps Bash/PowerShell/WebFetch, and `--fallback-model`, `--plugin-dir`/`--plugin-url`, `--betas`, `--brief`, `--environment` and `--forward-subagent-text` do nothing. `-w/--worktree` exists only inside `run_print_mode`, so `halo -w` edits the real working tree. — Verified: `build_controller(_build_parser().parse_args(["--restricted","--fallback-model","or:mock/other","--betas","x-beta",...]))` gives a session with a Bash tool, `fallback_models == []` and `cli_flags == {"resolved_plugin_roots": []}`. — Fix: pass `cli_flags=cli_flags_from_args(args)` from `build_controller`. Move worktree creation and `_worktree_created_path` into a helper both launch paths call before `build_session`. Add one TUI-path test per flag.
3. **major** — `halo_harness/agent/loop.py:1208-1230` — `apply_next_fallback_model` switches with `self.set_model(ref, profile, self.creds)`, which keeps the primary provider's credentials. A cross-provider fallback (`or:` primary with a `dbx:` fallback, or the reverse) therefore sends the fallback request to the primary's base URL with the primary's key and fails. Only same-provider fallback can work. — Verified: scratch Session `or:mock/...` with `fallback_models=["dbx:databricks-glm-5-3"]`. After `apply_next_fallback_model()` the provider is databricks, but `creds.base_url=https://openrouter.ai/api/v1` and `creds.api_key` is the OpenRouter key. — Fix: resolve credentials per entry with the same `_resolve_creds(ref, settings)` `/model` uses (keep the resolver on the Session), and skip an entry whose provider has no credentials.
4. **major** — `halo_harness/agent/loop.py:1232-1270` + `loop.py:3274-3282` — The notice says "for the rest of this turn" and the code comment says the primary is retried each turn, but `_turn_inner` only re-seeds `_fallback_remaining`.
