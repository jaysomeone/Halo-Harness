# Halo Harness 2.0.2 — API Research

Facts fetched live via WebFetch on docs, or `curl` on public key-less JSON
endpoints. No credentials sent. Each fact cites its source URL. "Could not
verify" is stated wherever a fetch failed or was inconclusive.

## 1. OpenRouter

**GET /api/v1/credits** — spec: https://openrouter.ai/openapi.json (`/credits`).
**Requires a Management key** ("Get total credits purchased and used... Management
key required."). Shape: `{"data": {"total_credits": 100.5, "total_usage": 25.75}}`
(both `number`/double; unit is OpenRouter credits, ≈USD, not explicitly labeled).

**GET /api/v1/key — not `/auth/key`.** Same spec. **Correction to the brief:**
`/auth/key` doesn't exist; the real path is `GET /api/v1/key`. `/auth/keys` and
`/auth/keys/code` are POST-only OAuth code-exchange endpoints for *creating* a
key, unrelated to reading the current one. `/key` needs only the session's own
key. Fields (from the spec example): `label, limit, limit_remaining, limit_reset,
usage, usage_daily, usage_monthly, usage_weekly, byok_usage(+_daily/_monthly/_weekly),
include_byok_in_limit, is_free_tier, is_management_key, is_provisioning_key,
creator_user_id, expires_at, free_model_daily_requests{limit,remaining,used},
allowed_data_regions[global|europe|us], rate_limit{interval,requests,note:"deprecated"}`.

**GET /api/v1/endpoints/zdr — confirmed to exist.** Same spec, summary "Preview
the impact of ZDR on the available endpoints." It's a **global, unscoped**
listing, not per-model: `{"data": [PublicEndpoint, ...]}`. No prose states an
access requirement (unlike `/credits`); a generic 403 "management keys only"
error schema is attached but that's reused across several unrelated endpoints
in the spec too — **could not verify if a regular key can call it.**

**GET /api/v1/models/{author}/{slug}/endpoints** — same spec, schemas
`ListEndpointsResponse`/`PublicEndpoint`. Top level: `{data:{id,name,created,
description,architecture,endpoints:[PublicEndpoint...]}}`. Full confirmed
`PublicEndpoint` field list: `context_length, latency_last_30m, max_completion_tokens,
max_prompt_tokens, model_id, model_name, name, native_tools,
perf_last_30m_by_workload, pricing{prompt,completion,image,request — decimal USD
strings}, provider_name, quantization, status, supported_parameters,
supports_image_reference, supports_implicit_caching,
supports_multiple_audio_references, supports_tool_choice, supports_voice_cloning,
tag, throughput_last_30m, uptime_last_1d/_30m/_5m`. `quantization` enum: `int4,
int8, fp4, mxfp4, nvfp4, fp6, fp8, mxfp8, fp16, bf16, fp32, unknown`. Latency/
throughput are percentile objects `{p50,p75,p90,p99}`; `perf_last_30m_by_workload`
breaks the same stats out per workload and is "only visible when authenticated
with an API key or cookie." **No data-policy/training boolean field exists on
`PublicEndpoint`** — ZDR status isn't inline; you must cross-reference the
separate `/endpoints/zdr` listing by `model_id`+`provider_name`, or set
`provider.zdr`/`provider.data_collection` at request time.

**Request-time provider routing** — https://openrouter.ai/docs/features/provider-routing.md
+ `ProviderPreferences` schema in the openapi spec:
- `provider.zdr` (bool|null): restrict routing to ZDR-only endpoints.
- `provider.data_collection` (`"allow"|"deny"|null`, default `allow`): allow =
  "providers storing user data non-transiently and may train on it"; deny =
  providers with no data collection.
- `provider.order` (provider-slug array|null): try in order, falls back unless
  `allow_fallbacks` is false.
- `provider.sort` (`"price"|"throughput"|"latency"|"exacto"`, or object
  `{by,partition}`): "disables default load balancing when specified."
- `provider.allow_fallbacks` (bool, default `true`).
- `provider.require_parameters` (bool, default `false`): drop providers that
  don't support all requested parameters.
- `provider.quantizations` (array from the Quantization enum above).
- Also present: `max_price`, `only`/`ignore` (provider allow/deny lists),
  `enforce_distillable_text`.

**Per-model region info: could not verify it exists.** No `region` field on
`PublicEndpoint`, `ListEndpointsResponse`, or the public `GET /api/v1/models`
list (curled directly, no key needed: 462 models, fields = `architecture,
canonical_slug, context_length, created, default_parameters, description,
expiration_date, hugging_face_id, id, knowledge_cutoff, links, name,
per_request_limits, pricing, reasoning, supported_parameters, supported_voices,
top_provider` — no region). Only region-shaped things found: `allowed_data_regions`
on `GET /key` (account/key-level, not per-model); enterprise regional domains
`eu.openrouter.ai`/`us.openrouter.ai` (route all traffic, no per-model metadata);
a schema named `PrivateEndpointDeclaredRegion` exists for self-registered
private/BYOK endpoints only (fields not fetched) — not part of the public catalog.

## 2. OpenAI

**GET /v1/models** — https://developers.openai.com/api/docs/api-reference/models/list
(platform.openai.com docs now redirect into `developers.openai.com/api/...`).
`{"object":"list","data":[{id, object:"model", created, owned_by,
shutdown_date (optional/null)}]}`. Moderate confidence — summarized from a
rendered page, and the endpoint needs a key so it couldn't be curled to cross-check.

**Responses API, reasoning + tools** — https://developers.openai.com/api/docs/guides/reasoning.
`reasoning.effort` values: **`none, minimal, low, medium, high, xhigh, max`**
(model-dependent; `minimal` explicitly unsupported on GPT-6.1 Sol). Multi-turn
reasoning replay, two approaches: (1) pass `previous_response_id` — "carries
forward reasoning context automatically"; (2) manual replay — "preserve every
output item, append the next user message, and replay the complete history,"
including reasoning items whose `encrypted_content` property (present when
`store:false`) you pass back in. **Could not verify** the full request/response
field list or streaming event-type names — a fetch of `.../responses/methods/create`
returned a truncated page, surfacing only `input` plus unconfirmed fragments
(`access_programs, background, context_management, conversation, include`).

**Tools + reasoning_effort rejected on Chat Completions — two-tiered, not one
rule.** https://developers.openai.com/api/docs/guides/reasoning: "Use the
Responses API for function calling. Chat Completions does not support function
calling with GPT-6 Astra or GPT-6.1 Sol." https://developers.openai.com/api/docs/guides/migrate-to-responses:
"Starting with GPT-5.4, Chat Completions does not support tool calling with
`reasoning_effort` values other than `none`." / "GPT-6 Astra and GPT-6.1 Sol
require the Responses API for tool calling." I.e. **GPT-5.4+ only rejects tools
when effort ≠ none; GPT-6 Astra/6.1 Sol reject tool calling on Chat Completions
unconditionally.** Literal runtime error text: **could not verify**.

**Org usage/costs endpoints** — https://developers.openai.com/api/reference/administration/overview:
"To access these endpoints, create an Admin API key
(platform.openai.com/settings/organization/admin-keys). Admin API keys cannot
be used for non-administration endpoints." Confirms an Admin-key-gated
"administration" family exists, but **exact paths (e.g. `/v1/organization/usage/completions`,
`/v1/organization/costs`) and response shapes could not be re-confirmed** —
every attempt to load a page printing them 404'd or returned nav-only fragments.

## 3. Codex CLI (openai/codex)

`docs/*.md` in the GitHub repo (listed via `api.github.com/repos/openai/codex/contents/docs`,
no auth) are now redirect stubs → `developers.openai.com/codex/...` →
`learn.chatgpt.com/docs/...`.

**`codex exec`** — https://learn.chatgpt.com/docs/non-interactive-mode. Alias
`codex e`. `--json`: "Outputs JSON Lines stream instead of text." Confirmed
event types: **`thread.started, turn.started, turn.completed, turn.failed,
item.started, item.completed, error`** (item types: agent messages, reasoning,
command executions, file changes, MCP tool calls, web searches, plan updates).
Example: `{"type":"turn.completed","usage":{"input_tokens":24763,"cached_input_tokens":24448,"output_tokens":122,"reasoning_output_tokens":0}}`.
Other flags: `--output-last-message`/`-o`, `--output-schema`, `--ephemeral`,
`--ignore-user-config`, `--ignore-rules`, `--skip-git-repo-check`, `--full-auto`
(deprecated). Resume: `codex exec resume [SESSION_ID]` with `--last`/`--all`.
Model: `--model`/`-m` (e.g. `gpt-6.1-sol`).

**Approval/sandbox for fully automatic runs** — https://learn.chatgpt.com/docs/developer-commands.
`--ask-for-approval`/`-a`: `on-request|never`. `--sandbox`/`-s`:
`read-only|workspace-write|danger-full-access`.
`--dangerously-bypass-approvals-and-sandbox` (alias `--yolo`): fully automatic,
"unsafe except in hardened environments." `--full-auto`: deprecated, docs say
prefer `--sandbox workspace-write`.

**MCP server config** — same page. `codex mcp add <name> -- <command...>`
(stdio) or `--url https://...` (HTTP), `--env KEY=VALUE` for stdio env vars.
One-off override: `-c key=value`. The fetched summary calls this "stored in
`~/.codex/config.toml`" — **ambiguous/unconfirmed**: may just describe where
persistent config normally lives, not that a one-off `-c` writes to disk.
Dedicated config-reference pages 404'd at both
`developers.openai.com/codex/config-reference` and
`learn.chatgpt.com/docs/config-reference` — **the `[mcp_servers.NAME]` TOML
shape could not be verified.**

**`codex login status` / auth storage** — https://learn.chatgpt.com/docs/auth.
Credentials at **`~/.codex/auth.json`** by default (`$CODEX_HOME`, default
`~/.codex`; configurable via `cli_auth_credentials_store`). Docs warn: "it
contains access tokens. Don't commit it, paste it into tickets, or share it in
chat." `codex login status` shows ChatGPT-login vs API-key auth; exact output
format not given (repo README separately says it exits `0` when credentials
are present). Auth methods: ChatGPT OAuth, device auth, API key, or access
token via stdin.

**Models/limits under a ChatGPT subscription: could not verify.** Docs only say
API-key auth has "some features that rely on ChatGPT workspace access or cloud
services... limited or unavailable," and mention "ChatGPT plan credits" without
specifics. No rate/session limits documented anywhere fetched. (Unconfirmed
hint: `gpt-5.3-codex`/`gpt-5.3-codex-spark` appear as distinct OpenAI ids on
models.dev, plausibly Codex-specific — not a documented gating fact.)

## 4. Anthropic

**GET /v1/models** — https://platform.claude.com/docs/en/api/models/list
(`docs.claude.com` 301s to `platform.claude.com`). `{"data":[ModelInfo...],
"first_id","has_more","last_id"}`. `ModelInfo`: `type:"model", id, display_name,
created_at, max_input_tokens, max_tokens, capabilities`. `capabilities` keys
always present: `batch, citations, code_execution, context_management
(+clear_thinking_20251015/clear_tool_uses_20250919/compact_20260112), effort
(+low/medium/high/max/xhigh), image_input, pdf_input, structured_outputs,
thinking (+adaptive/enabled)`. Example id: `claude-opus-5`.

**Admin API usage/cost reports** —
https://platform.claude.com/docs/en/api/beta/organization/usage_report/retrieve_messages
and .../cost_report. `GET /v1/organizations/usage_report/messages`: params
`starting_at`(required), `ending_at`, `bucket_width`(`1d|1h|1m`), `group_by`
(`account_id,api_key_id,context_window,inference_geo,model,service_account_id,
service_tier,speed,workspace_id`), `models, service_tiers, context_window,
limit, page`, account/key/workspace filters. Response: `{data:[{starting_at,
ending_at, results:[{account_id, api_key_id, cache_creation{ephemeral_1h_input_tokens,
ephemeral_5m_input_tokens}, cache_read_input_tokens, context_window,
inference_geo, model, output_tokens, server_tool_use{web_search_requests},
service_account_id, service_tier, uncached_input_tokens, workspace_id}]}],
has_more, next_page}`. `GET /v1/organizations/cost_report`: params `starting_at`
(required), `ending_at`, `bucket_width`(`1d` only), `group_by`(`description|
workspace_id`), `limit`(default 7, max 31), `page`. Response: same bucket
envelope with `results:[{amount (decimal string), context_window, cost_type
(code_execution|session_usage|tokens|web_search), currency:"USD", description,
inference_geo, model, service_tier, token_type, workspace_id}]`. Both example
`curl`s auth with the plain `X-Api-Key` header + `anthropic-version` — no
distinct admin header name; access is controlled by the key's Admin role, not a
different header scheme.

**`claude` CLI usage, non-interactively** —
https://code.claude.com/docs/en/commands.md,
https://code.claude.com/docs/en/cli-reference.md. **No non-interactive/print-mode
usage command exists.** `/usage` is interactive-only: "Show session cost, plan
usage limits, and activity stats. On a Pro, Max, Team, or Enterprise plan,
includes a breakdown of what counts against your plan limits." Aliases
`/cost`, `/stats`. It's merely listed among commands that "run immediately
without interrupting the response" (with `/status`,`/tasks`) — that's about not
blocking mid-turn, not `-p` support. What *is* scriptable: `claude auth status`
("Show authentication status as JSON... Exits with code 0 if logged in, 1 if
not") and `-p --output-format json` — neither reports usage/quota numbers.
**A harness needs the Admin API usage/cost reports above (different credential
than a subscription) or must scrape the interactive `/usage` output.**

## 5. TypeSafe Jev

**"Is Jev deterministic?" — could not verify the answer.** https://typesafe.ai
homepage FAQ lists the question verbatim, but the answer renders client-side and
isn't in static HTML. Tried: llms.txt-summarized read; raw-HTML grep for
"deterministic" with wide context; decoding Framer's `data-framer-name`
base64-ish attributes (a known CMS quirk) — this decoded one real string, but
unrelated marketing copy: "RLHF optimized LLMs for human preferences. We built
Jev to be natively used by machines, with new architecture, a parallel sampler,
and a new training algorithm - Reinforcement Learning for Calibrated Decisions";
a direct `/faq` path 404'd. That "parallel sampler" mention is *suggestive* of
non-determinism but not a documented guarantee — **treat Jev as non-deterministic
until TypeSafe confirms otherwise.**

**Usage/balance endpoint: could not verify one exists.** https://docs.typesafe.ai/llms.txt
lists a Python SDK "[Usage](https://docs.typesafe.ai/sdk/python/usage.md)" guide,
but it reads as SDK usage-pattern docs, not a billing/balance REST endpoint.

**Rate-limit headers** — https://docs.typesafe.ai/sdk/python/api/retries.md
confirms the SDK "honor[s] `Retry-After` and `retry-after-ms` response headers"
by default (`respect_retry_after=True`), confirming those header names exist
server-side even though no dedicated "rate limits" page was found.

**Python SDK retry/timeout defaults** — same page +
https://docs.typesafe.ai/sdk/python/api/constants.md. Max retries: default **2**
after initial attempt (3 total; `0` disables). Backoff: exponential, first delay
**0.5s**, doubles each attempt, capped **5.0s**, jitter **0.25**. Retry budget:
**30.0s** total per call. Default retried statuses: **408, 429, 500–599**.
Constants page separately lists a **10.0s** default timeout "per HTTP
operation" (likely per-request connect/read, distinct from the 30s whole-call
budget; not reconciled in the docs). Env vars: `TYPESAFE_API_KEY,
TYPESAFE_BASE_URL` (default `https://api.typesafe.ai`), `TYPESAFE_DEFAULT_MODEL`
(default `jev-latest`), `TYPESAFE_LOG_LEVEL`.

## Implications for the 2.0.2 brief

**Contradicts the brief:**
1. OpenRouter's "auth/key" endpoint doesn't exist — real path is **`GET /api/v1/key`**;
   `/auth/keys` is an unrelated POST-only OAuth code-exchange endpoint. Code
   targeting `/auth/key` will 404.
2. "Function tools + reasoning_effort rejected on chat completions" is really
   **two rules**: GPT-5.4+ rejects tools only when effort ≠ `none`; GPT-6
   Astra/6.1 Sol reject tool calling on Chat Completions unconditionally. A
   single blanket check misclassifies GPT-5.4 at default effort as broken.
3. Per-model region data doesn't exist on OpenRouter's public surface (not on
   `PublicEndpoint`, not on `/api/v1/models`). A per-model region column/filter
   has nothing to source from today — only account-level `allowed_data_regions`
   and enterprise regional domains exist.

**Three riskiest unknowns:**
1. **OpenAI org usage/costs exact paths** — confirmed Admin-key-gated, but exact
   path strings unconfirmed this session, and the doc domain has visibly moved
   (`platform.openai.com` → `developers.openai.com/api`). Smoke-test against a
   real Admin key before relying on a hardcoded path.
2. **Codex CLI under a ChatGPT subscription** — no documented model list, no
   rate/session limits, ambiguous `-c` persistence semantics. Verify empirically
   against a real logged-in `codex` binary rather than trusting the docs alone.
3. **Jev determinism is totally unconfirmed** — the FAQ answer is JS-rendered
   and unreachable by static fetch; the only lead ("parallel sampler") leans
   non-deterministic. Any 2.0.2 feature assuming Jev responses are cacheable/
   replayable/diffable rests on an undocumented assumption — worth a direct
   question to TypeSafe or a browser-rendered read before building on it.
