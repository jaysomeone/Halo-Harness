## 1. What Jev is (facts gathered 2026-09-30 from typesafe.ai and docs.typesafe.ai)

- TypeSafe AI's Jev: "TypeSafe's first public System One Model, optimized
  for automation". Site dated 2026-09-28, "early access". Console at
  console.typesafe.ai, docs at docs.typesafe.ai.
- A System One model returns typed decisions with calibrated
  probabilities. It "does not generate text", has no tool calling, no
  streaming, no file editing. The docs say it is "not a drop-in replacement
  for the LLM behind Claude Code, Cursor, opencode, Copilot"; it is meant to
  run inside an agent for routing, scoring, validation and typed output.
- API: `POST https://api.typesafe.ai/v1/systemone`, header
  `Authorization: Bearer <TYPESAFE_API_KEY>`. Body: `state` (string, object
  or array), `model` (`jev-latest`), `questions` (map of named questions).
  Question types: `choice` (criteria = up to 255 named options; answer =
  `choice`, `probabilities`, `confidence`), `score` (2 to 10 ordered levels;
  answer = `score`, `legend`, `probabilities`, `confidence`), `noul` (yes/no;
  answer = `noul` 0 to 1). `usage.input_tokens` / `output_tokens`.
- Model `jev-1.13.0`; aliases `jev-latest`, `jev-preview` (same today).
  64k tokens per request (32k for `state` plus the longest question). Text
  only; English primary. Price $0.042 per million input tokens, output free.
  Rate limits 100K tokens/s and 40 requests/s. Errors 401, 422, 429, 529
  (backoff). SDKs: `pip install typesafe-sdk` (Python 3.10+), JavaScript.
- Confidence = concentration of the probability mass; docs suggest 0.9+
  act, 0.5 to 0.9 caution, below 0.5 do not act, tuned per domain.
- Determinism: the docs never state it. Training is "reinforcement learning
  for calibrated decisions"; there is no text sampling, which is the likely
  basis for "less non-deterministic". Repeatability must be measured.
- Known issues (Jev 1.13 page): literal reading of instructions; no
  reliable counting, arithmetic or date comparison; accuracy drops with
  irrelevant state ("context rot"); injected instructions in the state can
  steer answers; contradictory instructions and criteria confuse it; no
  arithmetic identities across separate questions; cannot generate text.
- Claude Code plugin: `claude plugin marketplace add typesafe-ai/skills`
  then `claude plugin install typesafe@typesafe-ai`, skill
  `/typesafe:typesafe-ai` (repo github.com/typesafe-ai/skills). rolo-claude
  reads plugin skills, so this should load unchanged; verify.
- OpenRouter also lists `typesafe/jev-router`: a chat-completions router
  that "picks the best model and reasoning effort for each request", running
  on Jev. Listed context 1M, variable pricing, no supported parameters or
  endpoints published. This is a different product from the decision API.

## 2. Where Jev could fit rolo-claude

Hard rule first: Jev never gates tool calls or permissions. rolo's harness
has no classifier and no cyber blocks; that stays. Candidates, each a place
where the harness today uses a heuristic or a small-model call:

1. Role and model routing per request (v2 roles): `choice` on intent plus
   `score` on complexity, confidence-gated, picks orchestrator, coder or
   small. This is the docs' own intent-routing pattern.
2. Automatic reasoning effort per request, what Jev Router does: `score`
   on reasoning demand mapped into the route's accepted effort set (items
   19 and 20 vocabulary).
3. Tool-call repair: `choice` over the tool catalog (up to 255 options) to
   recover the intended tool, and a `choice` of repair strategy. Today this
   is difflib in `agent/repair.py`.
4. Lazy MCP and ToolSearch relevance: one `noul` per deferred tool, batched
   in a single request, to pick which tools to load. Today it is name and
   description matching.
5. Compaction and pruning: `noul` "still needed" per old tool result and a
   `choice` of files to re-read after compaction.
6. Turn completion and loop breaker: `noul` "the last message completed the
   request", "the repeated call is making progress".
7. `/improve`: `choice` over failure categories, `score` of candidate value.
8. Catalog and picker: near-miss model slug correction, family
   classification fallback.
9. Quality gate for the small role: `score` the small model's answer and
   escalate on low confidence (confidence-gated routing).

## 3. Design sketch

- `providers/typesafe.py`: stdlib client through `default_tls_context`,
  bounded connect, 429 and 529 backoff, request builder, typed answers.
- `decider.py`: `Decider` with `choice()`, `score()`, `noul()`, batching of
  independent questions into one request, thresholds, a cache keyed by a
  hash of state plus questions, and two backends: `typesafe` and `none`
  (today's heuristics). A Jev failure never blocks a turn.
- Config: `~/.rolo-claude/config.json` `decider` block (provider, model,
  thresholds, max state tokens); key from `TYPESAFE_API_KEY` through the
  settings env chain; `init` provider list gains an optional TypeSafe entry.
- State builders per decision point: minimal, filtered, secrets redacted.
- Telemetry (H10): every decision logged as non-model-visible meta
  (question, answer, confidence, latency, cost); `stats --decider`.

## 4. Research and evaluation plan (before any code)

1. Account and key (rolo, console.typesafe.ai), confirm pricing, limits and
   the FAQ answer to "Is Jev deterministic?".
2. Repeatability: identical requests repeated across the decision types;
   compare probabilities and latency distributions.
3. Offline eval sets from existing session logs for candidates 1 to 7,
   labelled with Opus 5.5; measure agreement and calibration (confidence
   against accuracy).
4. Cost and latency against the current small-model calls for the same
   decisions.
5. Pick the first shipping set (likely 2, 3, 4 and 9), write
   `docs/harness/JEV-design.md`, then milestones with the usual three-platform
   verification.
6. Separately try `or:typesafe/jev-router` as a chat route: tool calling,
   reasoning replay, cost reporting; document it like `openrouter/auto`.

## 6. jev-router assessment (2026-10-03, rolo asked "is this worth using?")

`typesafe/jev-router` on OpenRouter (created late September 2026) is a
meta-router: Jev picks a target chat model and a reasoning effort per
request and forwards it. The listing publishes no target models, no
pricing beyond "variable", no benchmarks, and an empty endpoint list.
Recommendation given to the owner: not as a Halo session model (it hides
the model choice, makes cost per turn unpredictable, switches model
families under the per-family repair layer and the prompt cache, may
override the effort Halo sets, and adds a decision hop). Keep it as an
EXPERIMENT line in this item: try `or:typesafe/jev-router` for ten turns,
record which models OpenRouter reports it chose and the cost, document it
next to `openrouter/auto`. The value for Halo is the Jev decision API
(effort selection, repair choice, ToolSearch relevance) under Halo's own
control, which is what sections 2 to 4 already plan.

Owner's decision (2026-10-03): leave jev-router as a parked idea, not
scheduled in any version ("we can leave that as an experimental idea...
save it for an idea later; I like how halo gives us the control"). The Jev
decision API work in sections 2 to 4 stays in the 2.0.4 pack.
