# Halo 2.0.2 round D: the organization features left from round 7, and two small leftovers

Read plans/WORKER-RULES.md first and follow it exactly (writes of 250 lines
or fewer per call, no sub-agents, hermetic tests with BRIDGE_TEST_HOME /
BRIDGE_STATE_DIR exported yourself even for one module, no commit, no push,
hand-back format RESULT LINES / FILES TOUCHED / WHAT YOU FOUND). Never add
safety or refusal logic. Never write the owner's real paths into any file.
Design context: plans/2.0.2-round7-init-wizard-brief.md section 3b (the
Paperclip-derived org features) and docs/ORGS.md. Each item gets a test
that fails before and passes after.

1. Org templates with preview and install: `halo org install <name>` and
   `/org install <name>` copy a shipped or saved template into
   `~/.halo/orgs/` (refusing to overwrite without `--force`), each shipped
   template carries a one-line README description shown by `/org list` and
   the wizard's Organizations step.
2. Approval gates: a position with `requires_approval: true` holds its
   result as a pending card in the dock (accept, edit the instruction and
   re-run, or stop) before the parent continues; print mode prints the
   result and waits on stdin the way other asks do; `--yes`/`dontAsk`
   accept automatically.
3. `halo org export <name> [file]` and `halo org import <file>` for orgs
   and `halo roles template export|import` for role templates: plain JSON,
   validated on import (role names, reports, budgets), with a clear error
   listing what is wrong.
4. `/org resume` (and `halo org resume <session-id>`): continue an
   interrupted org run from the task board (open and claimed tasks become
   the work list, done tasks are kept), with the org's caps and budget
   restored from the run record.
5. Two leftovers: `/mcp` `e` with a non-vim `$EDITOR` no longer passes a
   vim-only `+<line>` argument (use the editor's own line syntax for vim,
   nano, code, subl; otherwise open the file plain); `halo mcp learned
   --forget <endpoint>` clears a learned tools-rejected rule before its TTL.

Docs: docs/ORGS.md (install, approval gates, export/import, resume),
docs/COMMANDS.md, CHANGELOG [2.0.2] (fold into the organizations item).
Verify with the three suites from the repo root with PYTHONPATH set
(`tests/run_all.py` once, then `test_tui.py`), then `git checkout --
docs/harness/tui-snapshots`; report the three RESULT lines and list
anything left undone.
